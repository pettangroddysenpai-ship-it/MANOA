CheckPoint - Enterprise Firewall

Definition

CheckPoint Software Technologies is a global leader in cybersecurity solutions and enterprise firewalls. Its flagship solution, CheckPoint Firewall, is a hardware or virtual appliance that ensures network perimeter security. It integrates stateful firewall, VPN, intrusion prevention (IPS), content filtering, anti-bot, and sandboxing (Threat Emulation) features.

What is CheckPoint used for at Matrix Telecom?

At Matrix Telecom, CheckPoint is used as a perimeter security solution for enterprise clients requiring a high level of protection. CheckPoint appliances (5000 series, 14000 series, or virtual on VMware) are deployed for:

  • Protecting clients' internal networks from external threats.
  • Creating site-to-site VPN tunnels to interconnect branches.
  • Application and web content filtering (URL filtering, Application Control).
  • Advanced protection against malware and zero-day attacks (Threat Emulation).

How It Works

CheckPoint Architecture

CheckPoint uses a three-component architecture:

  • Security Gateway: The physical or virtual appliance that inspects traffic and enforces security policies.
  • Security Management Server: The central server hosting the policy database, logs, and certificates. It communicates with gateways via the SIC (Secure Internal Communication) protocol.
  • SmartConsole: The graphical management interface (Windows thick client) that allows administrators to configure policies, monitor events, and manage users.

Key Features

  • Stateful Firewall: Packet inspection with connection state tracking (INSPECT engine).
  • IPSec / SSL VPN: Secure tunnels for remote access (Remote Access VPN) or site interconnection (Site-to-Site VPN).
  • Threat Prevention: IPS, Anti-Virus, Anti-Bot, Threat Emulation (sandboxing), Threat Extraction.
  • Application Control & URL Filtering: Control of applications (Facebook, WhatsApp, etc.) and website filtering by category.
  • Identity Awareness: Integration with Active Directory to enforce policies based on user identity (not just IP address).
  • Mobile Access: Secure access to internal resources from mobile devices.
  • High Availability (HA): Active/passive or active/active cluster with state synchronization.
  • Logging & Monitoring: Centralized logs on the management server, event correlation, real-time alerts.

Step-by-Step Configuration

Step 1: Appliance Initialization (First Time Configuration)

1. Connect the appliance to the network (management port).
2. Use a console cable for CLI access (or connect via default IP 192.168.1.1).
3. Log in with admin / admin (default).
4. Configure the management IP address:
   - Run "sysconfig" from the console.
   - Choose "Configure this gateway as a Security Gateway only" (or Management + Gateway if combined).
   - Set the IP address, mask, default gateway.
   - Set the admin password.
   - Reboot.

Step 2: Creating a Security Policy (SmartConsole)

1. Open SmartConsole from an administration workstation (Windows).
2. Connect to the Management Server with the administrator account.
3. Go to "Security Policies" > "Access Control" > "Policy".
4. Create rules (order = priority from top to bottom):

   # | Name          | Source              | Destination          | Service        | Action | Track
   1  | Internet      | Internal_Net (10.0.0.0/8) | Any          | http,https,dns | Accept | Log
   2  | DMZ           | Internal_Net         | DMZ_Net (172.16.0.0/24) | Any (authorized services) | Accept | Log
   3  | VPN_SiteA     | SiteA_Net (192.168.1.0/24) | Internal_Net | Any           | Accept | Log
   4  | Block_Streaming | Internal_Net      | Any              | Applications: Streaming(Netflix,YouTube) | Drop | Log
   5  | Block_Malware | Any                  | Any              | Threat: Malware site | Drop | Alert
   6  | Default       | Any                  | Any              | Any           | Drop   | Log

5. Click "Install Policy" to push the policy to the Security Gateway.
6. Confirm and verify that the status changes to "Installed".

Step 3: Site-to-Site VPN Configuration

1. In SmartConsole, go to "Security Policies" > "VPN" > "Communities".
2. Create a new "Site-to-Site" community.
3. Add both partner gateways (in "Gateways").
4. In "VPN Domains", define the local networks of each site.
5. Configure IKE parameters (Phase 1):
   - Encryption: AES-256
   - Hash: SHA-256
   - DH Group: Group 14 (2048-bit)
   - Lifetime: 86400 seconds
6. Configure IPSec (Phase 2):
   - Encryption: AES-256
   - Hash: SHA-256
   - PFS: DH Group 14
   - Lifetime: 3600 seconds
7. Go to "Access Control" and add a rule allowing traffic between the VPN domains.
8. Install Policy.

Step 4: Monitoring and Logs

1. In SmartConsole, open "Logs & Monitor" > "Logs".
2. Use filters to search:
   - "blade: Firewall" - All firewall events
   - "action: Drop" - Blocked connections
   - "action: Accept" - Allowed connections
3. Use "SmartView Monitor" to view real-time traffic, VPN connection status, gateway CPU/RAM load.

Practical Example at Matrix Telecom

Use Case: CheckPoint deployment for a banking client in Yaoundé.

Requirements:
  • Protection of the banking network (100 workstations) against external attacks.
  • Strict application filtering: only web browsers and authorized banking applications.
  • Site-to-site VPN between headquarters and the remote branch (Matrix fiber link).
  • SSL VPN for remote employee access while traveling.
  • Threat Prevention to block malware and intrusion attempts.

Configuration implemented:
  • Appliance: CheckPoint 5600 (gateway) + virtual Management Server on Matrix infrastructure.
  • Policy: Strict rules, only ports 80, 443, DNS, and banking applications are allowed.
  • Identity Awareness integrated with the bank's AD to track connections by user.
  • Threat Emulation enabled to analyze downloaded files in a sandbox.
  • Logs centralized on the management server with 90-day retention.
  • HA configured between two appliances in active/passive mode for maximum availability.

Result: The bank benefits from enterprise-level security, with monthly reports provided by Matrix on blocked threats and traffic trends.

Tools Used

SmartConsole - Main management interface (Windows client). Allows complete configuration: policies, VPN, network objects, administrators, logs, monitoring.
Usage: Install SmartConsole on a Windows workstation connected to the Management Server. Use the "Gateways & Servers" tab to manage objects.

SmartView Monitor - Real-time monitoring tool. Displays traffic, VPN connections, performance, alerts.
Usage: Accessible from SmartConsole or standalone. Use the "Traffic", "VPN", "System Health" tabs.

SmartLog - Log search engine with web interface. Allows fast searches across billions of logs.
Usage: Launch SmartLog from SmartConsole, use filters by IP address, user, application, action.

CLI (Expert mode) - Command line access on the gateway in expert mode.
Usage: SSH to the gateway, type expert to switch to expert mode (root password).

Useful CLI commands: 
fw stat                   # Firewall status (active blades)
fw ctl pstat              # Firewall statistics
fw tab -t connections -s  # Active connections
cphaprob stat             # HA cluster status
vpn tu                     # VPN tunnel status
cpview                    # Performance overview
netstat -rn               # Routing table
cpconfig                  # Gateway configuration
ls -l $FWDIR/log          # Log location

CheckPoint Management API - REST API to automate policy management. Useful for script integration.
Usage: curl -k -X POST https://management-server:443/web_api/login -d '{"user":"admin","password":"pass"}'

Tip for the Intern

Good to know:
  • CheckPoint is a powerful but complex security solution. The CCSA (CheckPoint Certified Security Administrator) certification is an excellent addition to your resume.
  • In SmartConsole, the order of rules is crucial. Rules are evaluated from top to bottom. The last rule is "Drop Any Any" by default.
  • Always check the logs after installing a policy to ensure it is not blocking legitimate traffic.
  • Use "Install on all gateways" mode with caution. Test first on a lab gateway.
  • SIC (Secure Internal Communication) must be established between the gateway and the management server before any configuration. Use cpca cert -p to reset SIC if needed.
  • CheckPoint licenses are per blade (Firewall, VPN, IPS, etc.) and per subscription. Check the validity period.
  • In case of problems, logs are your best ally. Use fw log in real time on the gateway.

Exercise

Task 1: Create and Install a Simple Firewall Policy in SmartConsole

Matrix Telecom uses CheckPoint firewalls at the network perimeter for premium clients. Writing a security policy that allows web traffic while blocking everything else is a fundamental skill. In this task you will create a rule base, install it on a gateway, and verify connectivity.

  1. Launch SmartConsole and connect to the management server with your credentials.
  2. Navigate to Security Policies > Policy and add a new rule at the top.
  3. Configure: Source = "Internal_Net" (object 10.0.0.0/8), Destination = "Any", Service = "HTTP, HTTPS, DNS", Action = "Accept".
  4. Add a second rule with Source = "Any", Destination = "Any", Action = "Drop" and enable logging.
  5. Click Install Policy and select the gateway object (e.g., "Mtx-FW-Yaounde").
  6. After installation, open the Logs & Monitor tab and confirm the policy name appears in recent logs.
  7. Verify from a test client that HTTP/HTTPS traffic is permitted and Telnet (port 23) is blocked.

Task 2: Configure a Site-to-Site VPN Tunnel Between Two CheckPoint Gateways

Matrix interconnects its Yaounde and Douala offices via an IPSec VPN. Understanding VPN configuration on CheckPoint is valuable for supporting client site-to-site requirements. This exercise guides you through the basic VPN community setup.

  1. In SmartConsole, go to VPN > Communities > New > Star Community.
  2. Name it "Matrix-Interco" and add the two gateway objects (Yaounde and Douala).
  3. Under VPN Settings, select IKEv1 with AES-128 encryption and SHA-1 hashing.
  4. Define the encryption domain for each gateway: internal subnets behind each firewall.
  5. Install the policy on both gateways.
  6. Initiate traffic between the two sites and run vpn tu on the gateway CLI to verify the tunnel is established.
  7. Check the VPN tunnel status in SmartConsole under VPN > Active Tunnels.

Troubleshooting

  • Policy not installed: Check SIC (status "Trust established" or "Communication error"). Check licenses.
  • Connection blocked: Check logs in SmartConsole. Verify if the accept/block rule matches. Check IPS and Application Control logs.
  • VPN not establishing: Check IKE phases (encryption parameters), certificates, VPN domains, firewall rules allowing VPN traffic.
  • Gateway unresponsive: Access via physical console or management port. Check CPU with cpview, processes with ps aux.
  • Logs not centralized: Check connectivity between gateway and management server (port 257). Check disk space on the management server.

Best Practices

  • Follow the principle of least privilege: only allow strictly necessary traffic.
  • Document each firewall rule with a clear name and description.
  • Regularly audit unused rules (suggested Cleanup Rule).
  • Use object groups (hosts, networks, services, applications) to structure the policy.
  • Regularly backup the management server database.
  • Enable alerts for critical events (intrusion attempts, administrator connections).
  • Update Threat Prevention blades regularly (latest signatures).
