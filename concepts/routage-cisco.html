CISCO - Routing and Switching

Definition

Cisco Systems is the global leader in network equipment for enterprises and service providers. Its operating system Cisco IOS (Internetwork Operating System) is the benchmark in routing and switching. Cisco equipment is recognized for its robustness, security, and functional richness (OSPF, BGP, EIGRP, VLANs, ACLs, VPN, etc.).

What is Cisco used for at Matrix Telecom?

At Matrix Telecom Yaoundé, Cisco is used in two main contexts:

  • Core Network: Cisco routers (ISR 4000 series, ASR 1000) handle IP/MPLS routing at Matrix's backbone.
  • Enterprise Clients: For business clients with advanced needs (multi-site, VPN, VLANs, high availability), Cisco is deployed with Catalyst 2960/3560/3750 switches and ISR routers.

How It Works

Cisco IOS - Execution Modes

  • User mode (>): Basic commands, information display. Limited access.
  • Privileged mode (#): Configuration and diagnostic commands. Access with enable.
  • Global configuration mode (config)#: Device configuration changes. Access with configure terminal.
  • Specific modes: interface, router, line, vlan to configure specific elements.

Key Features

  • VLANs (802.1Q): Network segmentation into isolated broadcast domains. Configuration on Catalyst switches.
  • STP (Spanning Tree Protocol): Prevents network loops at layer 2 by blocking redundant ports.
  • Inter-VLAN Routing: Routing between different VLANs via a router or a layer 3 switch (SVIs).
  • OSPF (Open Shortest Path First): Link-state dynamic routing protocol. Widely used in enterprise networks.
  • ACLs (Access Control Lists): Packet filtering based on IP addresses, protocols, ports. Used for perimeter security.
  • NAT (Network Address Translation): Translation of private IP addresses to public addresses.
  • DHCP Server/Relay: IP address assignment or relay to a central DHCP server.
  • VPN (IPSec, DMVPN, FlexVPN): Secure tunnels to interconnect remote sites.

Tools Used

PuTTY - SSH/Telnet/Serial console client. Used to access the Cisco command line via console cable or SSH.
Usage: Select Serial (console) or SSH (remote), enter the IP address or COM port (e.g., COM3, speed 9600).

Packet Tracer - Free Cisco network simulator for learning. Allows creating virtual network topologies and configuring Cisco devices.
Usage: Download from NetAcad, create a topology via drag-and-drop, configure via CLI.

GNS3 - Advanced network simulator that uses real Cisco IOS images. Allows complex topologies and integration with virtual machines.
Usage: Install GNS3, import a Cisco IOS image, create topology projects.

EVE-NG - Professional simulation platform (free Community edition). Web interface, multi-vendor support (Cisco, Juniper, etc.).
Usage: Deploy on VMware or bare-metal, connect via browser to build labs.

Cisco Configuration Professional (CCP) - Graphical tool for configuring Cisco ISR routers. Used more on older models, replaced by Cisco Network Assistant / DNA Center.

SecureCRT / Tera Term - Alternatives to PuTTY with more features (session management, scripts).

Tip for the Intern

Good to know:
  • The CCNA certification is an excellent goal. It will teach you Cisco fundamentals that are also applicable to other brands.
  • Always do write memory or copy running-config startup-config after a modification.
  • Use Packet Tracer at home to practice. It is free and very comprehensive.
  • In production, never do reload without verifying the configuration (show running-config).
  • Master show and debug: they are your best diagnostic tools.
  • STP can block ports if misconfigured. Use spanning-tree portfast on access ports.
  • ACLs have an "implicit deny" at the end. Place your rules in the correct order.
  • At Matrix, Cisco equipment is mostly used in the network core or for Premium clients. You will see them less often than MikroTik.

Exercise

Task 1: Configure OSPF on a Cisco Router in Packet Tracer

OSPF is the primary IGP used at Matrix Telecom's core network. Understanding OSPF neighbor establishment, area design, and route advertisement is essential for any network engineer. This task simulates a two-router OSPF setup, mirroring the link between a Matrix core router and a distribution switch.

  1. Open Packet Tracer and place two Cisco 4321 routers connected via a serial DTE-DCE cable.
  2. Assign IPs: R1 Gi0/0/0 = 10.0.1.1/30, R2 Gi0/0/0 = 10.0.1.2/30.
  3. Configure OSPF process 1 on both routers: router ospf 1, network 10.0.1.0 0.0.0.3 area 0.
  4. On R1, add a loopback 1.1.1.1/32 and advertise it in OSPF: network 1.1.1.1 0.0.0.0 area 0.
  5. Verify OSPF neighbor: show ip ospf neighbor should show FULL state.
  6. Check R2's routing table: show ip route ospf — the 1.1.1.1/32 route must appear.
  7. Ping from R2 to 1.1.1.1 to confirm bidirectional reachability.

Task 2: Configure VLANs and Inter-VLAN Routing (Router-on-a-Stick)

Matrix frequently deploys Catalyst switches with multiple VLANs for client segmentation. This task teaches you how to create VLANs on a switch, configure trunk ports, and route between VLANs using a Cisco router — a common design for SME clients.

  1. On a Cisco 2960 switch, create VLAN 10 (Sales) and VLAN 20 (Admin): vlan 10, name Sales, vlan 20, name Admin.
  2. Assign interfaces Fa0/1 to VLAN 10 and Fa0/2 to VLAN 20: switchport access vlan 10.
  3. Configure Gi0/1 on the switch as trunk: switchport mode trunk.
  4. On the router, configure subinterfaces: Gi0/0.10 with IP 192.168.10.1/24 and dot1Q 10; Gi0/0.20 with IP 192.168.20.1/24 and dot1Q 20.
  5. Connect two PCs: PC1 in VLAN 10 (IP 192.168.10.10/24) and PC2 in VLAN 20 (IP 192.168.20.10/24).
  6. Ping from PC1 to PC2 — if routing works, the ping succeeds. If not, check trunk and subinterface config.

Troubleshooting

  • No connectivity: Check show ip interface brief, show ip route and logs (show logging).
  • VLAN issue: Check the trunk, access port modes, native VLAN.
  • OSPF not converging: Check neighbor relationships, area IDs, declared networks.
  • ACL too restrictive: Check show access-lists, rule order, interface application (in/out).
  • Network loop: CPU at 100%, check STP, use show spanning-tree.
  • Lost password: Recovery procedure via ROMmon mode (boot interrupt, configuration register modification).

Best Practices

  • Document all configurations (topology, IP addressing, VLANs, ACLs).
  • Use strong passwords for enable and SSH access.
  • Configure banners (legal notice): banner motd % Authorized access only %
  • Use NTP to synchronize device clocks.
  • Enable AAA (TACACS+/RADIUS) for centralized access management if possible.
  • Regularly backup configuration to a TFTP/SCP server.
  • Limit SSH access to specific administration IPs.
