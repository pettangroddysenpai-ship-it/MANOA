Cacti — Open-Source Network Performance Graphing

← Back to Index

Definition & Overview

Cacti is a popular open-source web-based network monitoring and graphing tool. It leverages the SNMP protocol to collect data from network devices (routers, switches, servers) and stores the collected metrics in RRDTool (Round Robin Database) files. These RRD files efficiently store time-series data in a fixed-size circular buffer, enabling Cacti to keep years of historical data without consuming excessive disk space.

At Matrix Telecom, Cacti can be used to generate bandwidth utilization graphs for client uplinks, monitor CPU and memory trends on core routers, and visually track interface errors over time. While Cacti's alerting is limited compared to SolarWinds, its graphing capabilities are excellent and entirely free (GPL licensed).

How It Works — Technical Deep Dive

1. Data Collection Pipeline

Cacti's operation follows a five-step cycle that repeats every polling interval (default 5 minutes):

  1. Scheduler (Cron): The system cron triggers poller.php every 5 minutes. This PHP script is the heart of Cacti.
  2. Data Source Resolution: The poller reads the MySQL database to determine which devices need to be polled, what data queries (OIDs) to use, and the SNMP credentials for each device.
  3. SNMP Queries: For each device, the poller sends SNMP GET requests to retrieve the specified OIDs (interface octets, CPU load, etc.). Cacti supports SNMP v1, v2c, and v3.
  4. RRDTool Update: The poller passes each collected value to RRDTool, which updates the corresponding .rrd file. RRDTool handles data normalization, consolidation (averaging, max, min), and archiving into multiple Round Robin Archives (RRAs).
  5. Graph Rendering (On Demand): When a user navigates to a graph page in the Cacti web UI, the application calls RRDTool to generate a PNG image from the .rrd data. The graph is cached for performance.

2. RRDTool Deep Dive

RRDTool is the storage engine behind Cacti. An RRD file is created with a fixed size calculated from the configured number of data sources (DS) and round robin archives (RRA). Once created, the file never grows — old data is overwritten by new data.

# Creating a Cacti RRD file manually (what Cacti does automatically)
rrdtool create /var/www/cacti/rra/matrix_rtr_traffic_1.rrd \
  --step 300 \
  DS:traffic_in:COUNTER:600:0:10000000000 \
  DS:traffic_out:COUNTER:600:0:10000000000 \
  RRA:AVERAGE:0.5:1:576 \
  RRA:AVERAGE:0.5:6:1440 \
  RRA:AVERAGE:0.5:24:4380 \
  RRA:AVERAGE:0.5:288:3650 \
  RRA:MAX:0.5:1:576 \
  RRA:MAX:0.5:6:1440 \
  RRA:MAX:0.5:24:4380

Each RRA stores:
  - 1×576 = 576 values at 5 min intervals (48 hours)
  - 6×1440 = 1440 values at 30 min averages (30 days)
  - 24×4380 = 4380 values at 2 hour averages (1 year)
  - 288×3650 = 3650 values at 1 day averages (10 years)

3. Template System

Cacti uses a hierarchical template system to simplify configuration:

  • Host Templates: Define default data queries and graph templates for a device type (e.g., "Generic SNMP Device", "MikroTik Router", "Linux Server").
  • Graph Templates: Define the visual layout of a graph (lines, colors, legend, axis labels). Example: "Interface - Traffic (bits/sec, 64-bit count)".
  • Data Templates: Define the SNMP OID and data source type (COUNTER, GAUGE, DERIVE, ABSOLUTE) for a specific metric.
  • Data Queries: XML-based scripts that auto-discover multiple data sources from a device (e.g., discovering all interfaces via ifTable).

Step-by-Step: Adding a Device for Monitoring

  1. Log in to Cacti (http://cacti.matrixtelecom.local/cacti/, default: admin/admin). You will be prompted to change the password on first login.
  2. Navigate to Console > Devices > Add (+).
  3. Fill in the device details:
    • Description: Core-RTR-Douala-Management
    • Hostname: 10.200.10.1 (the OOBM management IP)
    • SNMP Version: Version 2
    • SNMP Community: matrix_ro
    • SNMP Port: 161
    • SNMP Timeout: 1000 ms
    • Device Template: Generic SNMP-enabled Device
  4. Click "Create". Cacti will immediately attempt to poll the device using SNMP. If successful, you will see green checkmarks next to system information fields (Hostname, Location, Uptime, etc.).
  5. Create Graphs: On the success page, click "Create Graphs for this Device". A list of available data queries appears:
    • Select "SNMP - Interface Statistics"
    • Check the interfaces you want to monitor (WAN, LAN, Management)
    • Select graph type: "In/Out Bits (64-bit)"
    • Click "Create"
  6. Add to Graph Tree: Navigate to Console > Graph Trees. Select your device's parent tree (e.g., "Matrix Infrastructure > Core Routers"). Find your device and add its graphs to the tree.
  7. Verify: Wait 10–15 minutes for two polling cycles. Then navigate to Graphs > (your tree) > Core-RTR-Douala. You should see interface traffic graphs beginning to populate.

Practical Example at Matrix Telecom Yaoundé

Matrix Context: Bandwidth Usage Graphs for Client Uplinks

Matrix Telecom's NOC uses Cacti to provide historical bandwidth data for both internal analysis and client-facing reports:

  • Client Uplink Graphs: Each client CPE has its WAN interface under Cacti graphing. When a business client complains of slow speeds, the NOC engineer pulls up the daily graph. If the "Inbound Traffic" line is flat at 50 Mbps (their plan limit), the client is saturating their link — no issue on Matrix's side.
  • Core Link Capacity Planning: The Yaoundé-to-Douala backbone link is graphed monthly. The 95th percentile bandwidth is used to determine when the link needs to be upgraded from 1 Gbps to 10 Gbps.
  • Interface Error Tracking: Cacti can graph CRC errors, runts, giants, and collisions. A sudden increase in CRC errors on a client port indicates a faulty SFP or damaged fiber — the NOC dispatches a technician to replace it before the link fails completely.
  • Wireless CPE SNR Graphs: Using custom OIDs from MikroTik or Ubiquiti MIBs, Cacti graphs signal-to-noise ratio and signal strength over time, helping detect RF interference trends.

RRDTool Command Line
Purpose: Direct manipulation and querying of RRD files (on the Cacti server)
Common commands: 
# Get RRD file metadata (DS names, RRA configuration)
rrdtool info /var/www/cacti/rra/device_traffic_123.rrd

# Fetch last 12 data points (1 hour at 5-min intervals)
rrdtool fetch /var/www/cacti/rra/device_traffic_123.rrd AVERAGE --start -1h

# Generate a custom graph (not through Cacti)
rrdtool graph /tmp/custom_bw.png \
  --start -1d --end now \
  --title "Custom Bandwidth Graph" \
  DEF:in=/var/www/cacti/rra/device_traffic_123.rrd:traffic_in:AVERAGE \
  DEF:out=/var/www/cacti/rra/device_traffic_123.rrd:traffic_out:AVERAGE \
  LINE1:in#00ff00:"Inbound" \
  LINE1:out#0000ff:"Outbound"

# Export RRD data to XML (backup)
rrdtool dump /var/www/cacti/rra/device_traffic_123.rrd > backup_123.xml
SNMP Command-Line Tools
Purpose: Verify SNMP reachability and OID values before adding to Cacti
Essential commands: 
# Test basic SNMP connectivity
snmpstatus -v 2c -c matrix_ro 10.200.10.1

# List all interface names
snmpwalk -v 2c -c matrix_ro 10.200.10.1 1.3.6.1.2.1.2.2.1.2

# Get interface speeds

# Use 64-bit counters (HC = High Capacity, recommended for > 50 Mbps links)

Tips for the Intern

Intern Tip:
  • Ask about Cacti at Matrix: "Does Matrix use Cacti for bandwidth graphing, or is it PRTG / LibreNMS / something else?" Even if the tool differs, the SNMP+RDD concept is universal.
  • Learn to read graphs: Being able to spot saturation, interface errors, packet loss, or CPU spikes on a Cacti graph is a core NOC skill.
  • Set up a lab Cacti instance: Install Cacti on a VM, add your laptop as a device, and graph its interface traffic. Experiment with templates.
  • Check the poller log first: When graphs aren't showing data, look at /var/log/cacti/poller.log. The error message usually points directly to the problem.
  • Never delete RRD files carelessly: If you delete an RRD file, all historical data for that device is gone. Export the data first if it's important.
  • Memorize common SNMP OIDs: Keep a cheat sheet of the OIDs you use most (interface octets, CPU, memory, uptime).
  • Use 64-bit counters for high-speed interfaces: Standard 32-bit counters (ifInOctets) wrap around at about 4.2 billion bytes (every 343 seconds on a 100 Mbps link). Always use ifHCInOctets/ifHCOutOctets for links above 10 Mbps.
  • Consider Spine for large deployments: If Matrix monitors many devices, Cacti's default PHP poller (cmd.php) will be too slow. Spine is a C-based poller that is 10–50x faster.

Exercise

Task 1: Create a Cacti Graph for a MikroTik Router Interface

This exercise teaches you how to add a device in Cacti, configure SNMP, and generate bandwidth graphs. At Matrix Telecom, MikroTik routers are widely used as CPEs and core devices. Being able to quickly add a new device and produce utilization graphs is essential for NOC engineers validating client links or troubleshooting congestion.

  1. Log in to the Cacti web interface (or your lab VM).
  2. Navigate to Console > Devices > Add.
  3. Enter the device IP (e.g., 192.168.88.1 for a MikroTik), set SNMP version to v2c, and community string matrix_ro.
  4. Select the "Generic SNMP-enabled Host" template and click Create.
  5. Once created, click Create Graphs for this Host and choose the interfaces you want to monitor (e.g., ether1-WAN).
  6. Add the selected graphs and wait 10-15 minutes for data to accumulate. View the graph under Graphs tab.
  7. Verify the graph shows inbound/outbound traffic. If no data appears, check /var/log/cacti/poller.log for SNMP errors.

Task 2: Build a Custom CPU Load Graph Using a Private OID

Matrix Telecom monitors CPU load on its MikroTik routers to detect overloads before they cause packet loss. In this task you will create a custom data template and graph template for the MikroTik CPU OID (1.3.6.1.4.1.14988.1.1.3.1). This simulates a real-world scenario where the built-in templates don't cover a vendor-specific metric.

  1. Go to Console > Data Templates > Add.
  2. Name it "MikroTik - CPU Load" and set the data source type to GAUGE.
  3. Enter the OID .1.3.6.1.4.1.14988.1.1.3.1 with SNMP community matrix_ro.
  4. Create a new Graph Template that uses this data template, with a line graph showing the CPU percentage.
  5. Assign the graph template to a MikroTik device and verify the graph populates after two polling cycles.
  6. Optional: add a 75% warning threshold line and a 90% critical line to the graph.

Creating Custom Templates

When the built-in Cacti templates don't meet your needs, create custom ones. Below is an example for monitoring MikroTik CPU load using the private MikroTik MIB:

Custom Data Template:
  Name:        MikroTik CPU Load
  Data Source: cpu_load
  OID:         1.3.6.1.4.1.14988.1.1.3.1 (hrProcessorLoad equivalent)
  DS Type:     GAUGE (value is instantaneous, not a counter)
  Min Value:   0
  Max Value:   100
  Heartbeat:   600 seconds (10 minutes — max allowed gap)

Custom Graph Template:
  Name:        MikroTik CPU Utilization
  Graph Type:  Line graph with area fill
  Items:
    AREA:cpu_load#ff6600:"CPU %"
    GPRINT:cpu_load:LAST:"Current\:%8.2lf"
    GPRINT:cpu_load:AVERAGE:"Average\:%8.2lf"
    GPRINT:cpu_load:MAX:"Max\:%8.2lf"

Performance Tuning for ISPs

  • Increase polling concurrency: In Console > Settings > Poller, set "Maximum Concurrent Processes" to 10–20 for networks with >500 devices.
  • Use Spine: Replace the default cmd.php poller with Spine. Compile from source: apt install cacti-spine. Configure in /etc/spine.conf.
  • Database optimization: Run mysqlcheck -o cacti -p weekly. Add indexes if the poller_output table is large.
  • Separate polling servers: For very large deployments, use multiple Cacti pollers that write to a shared database (requires manual configuration).
  • Cache graphs: Enable the RRDTool automatic caching feature in settings to avoid regenerating every graph on every page load.

Troubleshooting Guide

Symptom: Graph shows "NaN" (Not a Number)
  Cause: No data has been collected. Check SNMP reachability.
  Fix:   snmpwalk -v 2c -c matrix_ro 10.200.10.1 system

Symptom: Graphs are flat line at zero
  Cause: Wrong OID (e.g., using 32-bit counter on a 64-bit interface)
  Fix:   Change data template to use ifHCInOctets ifHCOutOctets

Symptom: Poller output log shows "ERROR"
  Cause: MySQL connection failure or PHP memory exhausted
  Fix:   Check MySQL service, increase memory_limit in php.ini

Symptom: "SNMP error" on device page
  Cause: Community string incorrect, ACL blocking, or SNMP disabled
  Fix:   Verify SNMP config on the device

Advantages and Limitations

Advantages: Free (GPL), efficient long-term storage with RRDTool, highly customizable, large community and template library, stable with thousands of devices.

Limitations: No built-in alerting (requires plugin or third-party tool), static PNG graphs (no interactive drill-down), dated web interface, steeper learning curve than commercial tools.
