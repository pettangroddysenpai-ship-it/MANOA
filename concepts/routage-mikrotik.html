MikroTik RouterOS

← Back to Routing Guide

Definition

MikroTik is a Latvian manufacturer of network equipment using its own operating system, RouterOS, based on the Linux kernel. It is widely used by ISPs and businesses for its flexibility, affordable cost, and advanced features. RouterOS supports routing, firewall, bandwidth management, VPN, DHCP, VLANs and more.

What is MikroTik used for at Matrix Telecom?

At Matrix Telecom Yaoundé, MikroTik is the most commonly used equipment. It is primarily deployed as CPE (Customer Premise Equipment) for residential and professional Internet clients. The most common models are the RB750, RB951, hAP, CCR and Cloud Core Router series.

How It Works

RouterOS Architecture

RouterOS is a complete network operating system. It uses interfaces (Ethernet, wireless, VLAN, bridges), routes (static and dynamic routing tables), firewall rules (filter, NAT, mangle), queues (bandwidth management) and services (DHCP, DNS, PPPoE, VPN).

Key Features

  • Bridge: Allows grouping multiple interfaces into a single network segment (virtual switch).
  • Firewall: Packet filtering with chain rules (input, output, forward) and NAT (srcnat, dstnat).
  • DHCP Server: Automatic IP address assignment to clients.
  • VLAN: Layer 2 network segmentation using 802.1Q.
  • PPPoE: Client/server connection for authenticated Internet access.
  • Routing: Static routing, OSPF, BGP, RIP.
  • Queue: Bandwidth management (PCQ, HTB) for QoS.
  • IPSec / OpenVPN / WireGuard: Creation of secure VPN tunnels.

Step-by-Step Configuration

Step 1: Initial Connection via WinBox

WinBox is MikroTik's official graphical tool. Download it from the MikroTik website. Connect the router via an Ethernet cable on port 2 (ports are numbered). Launch WinBox, click on the "Neighbors" tab to detect the device, select it and log in with user admin (no password by default).

Step 2: Basic Configuration (via CLI / Terminal)

/interface bridge add name=bridge1
/interface bridge port add bridge=bridge1 interface=ether2
/interface bridge port add bridge=bridge1 interface=ether3
/interface bridge port add bridge=bridge1 interface=ether4

/ip address add address=192.168.88.1/24 interface=bridge1
/ip dhcp-server setup

/ip pool add name=dhcp_pool ranges=192.168.88.10-192.168.88.200
/ip dhcp-server add name=dhcp1 interface=bridge1 address-pool=dhcp_pool lease-time=10m
/ip dhcp-server network add address=192.168.88.0/24 gateway=192.168.88.1 dns-server=8.8.8.8

Step 3: NAT Configuration (Shared Internet)

/ip firewall nat add chain=srcnat out-interface=ether1 action=masquerade

/ip dhcp-client add interface=ether1 disabled=no

Step 4: Basic Firewall Rules

/ip firewall filter add chain=input connection-state=established,related action=accept
/ip firewall filter add chain=input connection-state=invalid action=drop
/ip firewall filter add chain=input protocol=icmp action=accept
/ip firewall filter add chain=input src-address=192.168.88.0/24 action=accept
/ip firewall filter add chain=input action=drop

/ip firewall filter add chain=forward connection-state=established,related action=accept
/ip firewall filter add chain=forward connection-state=invalid action=drop
/ip firewall filter add chain=forward action=drop

Step 5: VLAN Configuration

/interface vlan add name=vlan10 vlan-id=10 interface=ether1
/interface vlan add name=vlan20 vlan-id=20 interface=ether1

/ip address add address=10.10.10.1/24 interface=vlan10
/ip address add address=10.10.20.1/24 interface=vlan20

/ip dhcp-server add name=dhcp_vlan10 interface=vlan10 address-pool=pool10
/ip dhcp-server add name=dhcp_vlan20 interface=vlan20 address-pool=pool20

Step 6: PPPoE Server Configuration

/interface pppoe-server server add interface=bridge1 service-name=Matrix-Internet

/ppp profile add name=client-profile local-address=10.0.0.1 remote-address=10.0.0.0/24
/ppp secret add name=client1 password=pass123 service=pppoe profile=client-profile

Practical Example at Matrix Telecom

Use Case: MikroTik hAP ac² as CPE for a residential client.

Scenario: A client subscribes to a 50 Mbps Internet offer. Matrix provides a pre-configured MikroTik hAP ac².

Setup:
  1. Port ether1 is configured as a DHCP client to obtain the public IP address from Matrix's fiber network.
  2. Ports ether2-ether4 are bridged on bridge1 (LAN) at 192.168.1.1/24.
  3. The DHCP server assigns IPs to the client's devices (range 192.168.1.100-254).
  4. NAT (masquerade) translates LAN traffic towards the WAN interface (ether1).
  5. Firewall rules block unsolicited incoming connections.
  6. Wi-Fi is configured on the 2.4GHz and 5GHz bands with SSID "Matrix-Client".
  7. A queue limits downstream bandwidth to 50 Mbps and upstream to 25 Mbps.

Typical Deployment Script: 
/interface bridge add name=bridge1
/interface bridge port add bridge=bridge1 interface=ether2
/interface bridge port add bridge=bridge1 interface=ether3
/interface bridge port add bridge=bridge1 interface=ether4
/ip address add address=192.168.1.1/24 interface=bridge1
/ip pool add name=pool-client ranges=192.168.1.100-192.168.1.254
/ip dhcp-server add name=dhcp-client interface=bridge1 address-pool=pool-client
/ip dhcp-server network add address=192.168.1.0/24 gateway=192.168.1.1 dns-server=8.8.8.8,1.1.1.1
/ip dhcp-client add interface=ether1 disabled=no
/ip firewall nat add chain=srcnat out-interface=ether1 action=masquerade
/queue simple add name=client-qos target=bridge1 max-limit=50M/25M

Tools Used

WinBox - Native Windows GUI for administering MikroTik routers. Allows full configuration, configuration backup, real-time monitoring (graphs, logs).
Usage: Download from mikrotik.com, connect by IP or MAC (discovered via Neighbors).

SSH / Terminal - Command line access via PuTTY or WinBox's integrated terminal. Useful for scripting and automation.
Usage: ssh admin@192.168.88.1

The Dude - Free network monitoring tool from MikroTik. Allows mapping and monitoring the status of network devices.
Usage: Install The Dude Server on a Windows or Linux machine, add devices to monitor.

Netinstall - RouterOS reinstallation utility. Allows restoring a bricked router or changing the firmware version.
Usage: Boot the router in Netinstall mode (hold the reset button), run Netinstall on a PC connected to port 1.

Best Practices and Security

  • Always change the default password for the admin user.
  • Disable unnecessary services (bandwidth-server, telnet, ftp, www if not used).
  • Set an allowed-router-ips to restrict SSH/WinBox access to specific IPs.
  • Enable automatic configuration backup to an FTP server or via email.
  • Use /system scheduler to schedule recurring tasks.
  • Keep RouterOS updated with the latest stable version.

Tip for the Intern

Good to know:
  • MikroTik represents 80% of the equipment you will handle at Matrix. Master WinBox and the CLI.
  • Always test a configuration in a non-client environment or outside peak hours.
  • Use /system backup save before any major modification.
  • Learn to read logs: /log print where topics~"critical"
  • In case of remote lockout, the reset button restores the default configuration (hold for 10 seconds).
  • Master NAT: srcnat for outbound traffic (masquerade), dstnat for port forwarding.
  • "Safe Mode" in WinBox allows undoing changes if the connection is lost.

Exercise

Task 1: Configure a MikroTik Router as a Simple CPE with NAT and DHCP

Matrix Telecom deploys MikroTik RouterBOARD devices as CPEs for hundreds of clients. Configuring basic Internet access (WAN connection, NAT, DHCP server, DNS) is the most common field task for interns. This exercise walks through a standard CPE setup from factory defaults.

  1. Connect to the MikroTik via WinBox or SSH (default IP 192.168.88.1, user admin, blank password).
  2. Reset the router to factory defaults: /system reset-configuration (answer yes).
  3. Set the WAN interface (ether1) to DHCP client: /ip dhcp-client add interface=ether1 disabled=no.
  4. Configure NAT (masquerade) for client traffic: /ip firewall nat add chain=srcnat out-interface=ether1 action=masquerade.
  5. Set up a DHCP server on the LAN interface (ether2) with pool 192.168.10.0/24.
  6. Add a DNS forwarder: /ip dns set servers=8.8.8.8 allow-remote-requests=yes.
  7. Connect a PC to ether2, verify it gets an IP via DHCP, and ping 8.8.8.8 to confirm Internet access.

Task 2: Configure a Simple Firewall (Filter Rules) to Protect the LAN

A default MikroTik allows everything. In production, Matrix enforces basic firewall rules to block inbound WAN traffic and limit inter-LAN access. This task hardens the default configuration with essential security policies.

  1. From WinBox/CLI, open IP > Firewall > Filter Rules.
  2. Add a rule to drop all inbound traffic from WAN: chain=input, in-interface=ether1, action=drop.
  3. Add a rule before the drop to accept established/related connections: connection-state=established,related, action=accept.
  4. Add a rule to accept ICMP from LAN: chain=input, in-interface=ether2, protocol=icmp, action=accept.
  5. Add a forward chain rule to drop all traffic from LAN to WAN on port 25 (block SMTP spoofing): protocol=tcp, dst-port=25, action=drop.
  6. Order the rules: the fast-track established rule must be first, followed by specific accepts, then the drop at the end.
  7. Test from a LAN PC: Internet still works, but port 25 outbound is blocked. Confirm with telnet smtp.gmail.com 25 (should time out).

Troubleshooting

  • No Internet connection: Check /ip dhcp-client print, /ip route print, /ping 8.8.8.8.
  • NAT not working: Check rule order and the output interface.
  • DHCP not distributing IPs: Check /ip dhcp-server print, ensure the pool is not exhausted.
  • WinBox connection impossible: Check connectivity, IP address, use MAC discovery (Neighbors).
  • Router slow / high CPU load: Check /tool profile to identify resource-heavy processes.
