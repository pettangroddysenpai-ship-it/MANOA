Cisco PAP2T - ATA Telephone Adapter

← Back to Routing Guide

Definition

The Cisco PAP2T (Phone Adapter with 2 Ports) is an analog telephone adapter (ATA - Analog Telephone Adapter) that allows connecting standard analog telephones (RJ11) to a VoIP (Voice over IP) network. It converts analog voice signals into IP packets transported over the Ethernet network. The PAP2T has two phone ports (FXS) and one Ethernet port (10/100 Mbps).

What is the PAP2T used for at Matrix Telecom?

Matrix Telecom offers VoIP telephony services to its professional clients. The PAP2T is used for:

  • VoIP Migration: Allow clients to keep their existing analog phones while switching to IP telephony.
  • Cost Reduction: VoIP calls are cheaper than traditional telephony (especially for international calls).
  • Flexibility: Easy addition of phone lines without new cabling.
  • Integration: The PAP2T works with any compatible SIP server (Asterisk, FreePBX, 3CX) that Matrix hosts for its clients.

How It Works

ATA Principle

The ATA bridges the Public Switched Telephone Network (PSTN) and the IP network. The analog phone is plugged into the FXS (Foreign eXchange Subscriber) port of the PAP2T. When the user picks up and dials a number, the PAP2T:

  1. Detects the hook-off.
  2. Dialing: Collects the dialed digits (DTMF).
  3. SIP Registration: Authenticates with Matrix's SIP server (registrar) using the account credentials (username, password, SIP domain).
  4. Call Establishment: Sends a SIP INVITE request to the server with the called number.
  5. Audio Codec: Negotiates the codec (G.711, G.729, G.726) and encapsulates voice in RTP (Real-time Transport Protocol) packets.
  6. Conversation: RTP packets travel between the two parties via the SIP server (or peer-to-peer if supported).
  7. Hang-up: Sends a SIP BYE to end the call.

Technical Specifications

  • 2 FXS ports (RJ11) for analog phones or fax.
  • 1 Ethernet port 10/100Base-T (RJ45).
  • Power: 5V DC, 2A (power adapter included).
  • Supported codecs: G.711 (a-law/μ-law), G.726, G.729a, G.723.1.
  • Protocols: SIP (RFC 3261), TCP/UDP, TFTP, HTTP, HTTPS.
  • Features: Caller ID, Call Waiting, Call Transfer, Three-Way Calling, Fax Pass-through (T.38).
  • Quality of Service (QoS): VLAN tagging (802.1p/q), DiffServ.
  • Configuration: Built-in web interface (HTTP/HTTPS) or via TFTP (automatic deployment).

Step-by-Step Configuration

Step 1: Physical Connection

  1. Plug the analog phone into the Phone 1 (or Phone 2) port of the PAP2T with an RJ11 cable.
  2. Connect the Ethernet cable (RJ45) from the PAP2T to the local network (switch or router).
  3. Plug the 5V power supply into the PAP2T.
  4. Wait for the "Power" and "Phone 1" LEDs to light up (green).

Step 2: Obtain the PAP2T IP Address

By default, the PAP2T obtains an IP address via DHCP. To find its IP:

  • Pick up the phone connected to the PAP2T.
  • Dial **** (4 presses on the star key) to access the voice menu.
  • Dial 110# to hear the IP address (e.g., "192.168.1.100"). Write it down.
  • Hang up. You can also check your router's DHCP table.

Step 3: Accessing the Web Interface

  1. Open a web browser (Chrome, Firefox, Edge).
  2. Type the URL: http://192.168.1.100 (replace with the found IP).
  3. Default credentials: admin / admin (user) or blank / admin (depending on firmware).
  4. If default credentials do not work, try:
    • User: admin / Password: (blank)
    • User: cisco / Password: cisco

Step 4: SIP Account Configuration (Line 1)

1. In the web interface, click on the "Voice" tab then "Line 1".
2. Configure the following parameters:

   - Line Enable: Yes
   - NAT Mapping Enable: Yes
   - NAT Keep Alive Enable: Yes

   - SIP Port: 5060 (default)
   - SIP Transport: UDP

   - Proxy and Registration:
        Proxy: sip.matrix.cm (or the Matrix SIP server IP)
        Outbound Proxy: (leave blank unless specified)
        Register: Yes
        Register Expires: 3600 (1 hour)

   - Subscriber Information:
        Display Name: John Doe
        User ID: 237691234567 (Matrix phone number)
        Password: SIPPassword
        Auth ID: 237691234567 (or the provided identifier)

3. Click "Submit All Changes" at the bottom of the page.

Step 5: Network Settings Configuration

1. Go to the "System" tab > "Internet Connection Type".
   - Connection Type: DHCP (or Static IP if fixed IP address).
   - If Static IP: fill in IP Address, Subnet Mask, Gateway, DNS.

2. "System" tab > "Network Settings":
   - Enable Web Server: Yes
   - Web Server Port: 80
   - Enable NAT Keep Alive: Yes

3. To improve voice quality (QoS):
   - DiffServ: 46 (EF - Expedited Forwarding for RTP packets)
   - VLAN ID: (set the voice VLAN ID if used)
   - VLAN Priority: 5 (Audio/Video)

Step 6: Advanced Configuration (Audio)

"Voice" tab > "Line 1" > "Audio Configuration" section:

- Preferred Codec: G.711u (best quality) or G.729a (reduced bandwidth)
- Use Pref Codec Only: No (allows negotiation)
- DTMF Tx Method: Auto (important for interactive voice servers)
- Fax Passthru: Yes (for fax)
- Fax Codec: G.711u

"Call Feature Settings" section:
- Call Waiting Serv: Yes
- Three Way Call: Yes
- Call Transfer: Yes
- Conference: Yes

Step 7: Save and Test

1. After "Submit All Changes", the PAP2T reboots (about 30 seconds).
2. Verify that the "Phone 1" LED is solid (registered).
3. Pick up the phone: you should hear a dial tone.
4. Dial a test number (e.g., the Matrix voice server or your mobile).
5. If it rings and the call is established, the configuration is successful.

Automatic Deployment via TFTP (for multiple PAP2Ts)

1. Set up a TFTP server on the network (e.g., SolarWinds TFTP, tftpd64).
2. Create an XML configuration file (e.g., SPAP2T.cfg):

<?xml version="1.0" encoding="UTF-8"?>
<flat-profile>
  <Proxy_1_>sip.matrix.cm</Proxy_1_>
  <Display_Name_1_>Matrix Client</Display_Name_1_>
  <User_ID_1_>237691234567</User_ID_1_>
  <Password_1_>secret</Password_1_>
  <Auth_ID_1_>237691234567</Auth_ID_1_>
  <Use_Pref_Codec_Only_1_>No</Use_Pref_Codec_Only_1_>
  <Preferred_Codec_1_>G711u</Preferred_Codec_1_>
  <Enable_Web_Server_>Yes</Enable_Web_Server_>
</flat-profile>

3. On the PAP2T, go to "System" > "Provisioning":
   - Profile Rule: tftp://tftp-server-ip/SPAP2T.cfg
   - Resync Trigger: 1 (on reboot)
   - Click "Submit All Changes" to apply.

Practical Example at Matrix Telecom

Use Case: Installing 20 PAP2Ts for a SME client in Yaoundé.

Context: The company "Cométro SARL" switches from analog telephony (Orange Cameroun) to Matrix VoIP to reduce its bills. It has 20 existing analog handsets and a virtual PBX hosted at Matrix.

Deployment:
  1. Matrix installs a FreePBX (Asterisk) server in its datacenter to host the VoIP solution.
  2. 20 PAP2Ts are pre-configured in the workshop via a TFTP provisioning file with extension numbers (201, 202, ..., 220).
  3. A technician goes to the client, plugs each PAP2T next to an analog phone.
  4. Each PAP2T automatically retrieves the configuration via TFTP (Profile Rule) and registers with the FreePBX server.
  5. Internal calls (between extensions 201-220) are free.
  6. Outbound calls (local, national, international) are routed through the Matrix SIP gateway.

Result:
  • 60% savings on the monthly phone bill.
  • Short-dialing between extensions.
  • Auto-attendant with voice menu (reception, sales, technical support).
  • Unified voicemail with email notification.
  • Ability to add extensions without new telephone cabling.

Tip for the Intern

Good to know:
  • The PAP2T is a simple but temperamental device. The SIP configuration must be exact (Proxy, User ID, Password). One typo and registration fails.
  • To find the PAP2T IP address without a screen, use the voice menu (**** then 110#).
  • If the "Phone 1" LED is blinking, the SIP account is not registered. Check credentials and network connectivity.
  • The G.711u codec offers the best audio quality but consumes 64 kbps per call. G.729a reduces to 8 kbps (useful for limited Internet connections).
  • For fax, use G.711u and reduce the fax speed to 9600 bps in fax settings.
  • The PAP2T supports VLAN tagging. Use it if the local network separates voice and data (voice VLAN).
  • In case of problems, check that SIP port (5060) and RTP ports (16384-16482) are not blocked by the firewall.
  • Factory reset is done by holding the Reset button for 10 seconds (or via code 732668# on the phone).

Exercise

Task 1: Configure a PAP2T ATA to Register with Matrix's SIP Server

The Cisco PAP2T is used by Matrix Telecom to provide analog phone service over VoIP. Configuring the ATA to register with the SIP proxy is a common deployment task. This exercise simulates setting up a new customer phone line from scratch.

  1. Connect the PAP2T to the LAN and power it on. Wait for the Power and Internet LEDs to stabilize.
  2. Find the PAP2T's IP from your router's DHCP lease list, then open its web interface in a browser (http://IP).
  3. Navigate to Admin Login > advanced > Voice > Line 1 (default password: admin).
  4. Set the following SIP parameters: Proxy = sip.matrixtelecom.cm, Register Expires = 3600, Display Name = "Client Name", User ID = 237XXXXXX, Password = provided SIP password.
  5. Set DTMF method to Auto and Preferred Codec to G.711a (or G.729 if bandwidth is limited).
  6. Click Submit All Changes and wait 30 seconds for the PAP2T to reboot.
  7. Check the Line 1 Status page: if "Registered" shows Yes, pick up the phone and confirm dial tone.
  8. Place a test call to the Matrix test number (provided by supervisor) and verify two-way audio.

Task 2: Troubleshoot a PAP2T That Fails to Register

Registration failures are the most common VoIP issue at Matrix. This task simulates real-world troubleshooting: a client reports no dial tone, and you must diagnose and resolve the problem from the NOC.

  1. Access the PAP2T web interface and go to Line 1 Status — note the registration state (e.g., "Not Registered").
  2. Check the Syslog (enable logging in the PAP2T under System tab) to see SIP error codes (e.g., 401 Unauthorized, 408 Timeout).
  3. If error 401: verify the SIP password is correct in the Line 1 configuration.
  4. If error 408: check that UDP port 5060 is not blocked on the firewall. Use telnet sip.matrixtelecom.cm 5060 from the client's LAN.
  5. If the firewall is blocking, add a NAT rule to allow UDP 5060 inbound and outbound for the PAP2T's IP.
  6. If SIP ALG is enabled on the router, disable it (SIP ALG often corrupts SIP headers on MikroTik and Linux devices).
  7. After each change, reboot the PAP2T and re-check Line 1 Status until it shows "Registered: Yes".

Troubleshooting

  • No dial tone: Check that the phone is plugged into the "Phone 1" port (not "Line"). Check the PAP2T power supply.
  • Phone LED blinking: The SIP account is not registered. Check:
    • That the SIP proxy is reachable (ping sip.matrix.cm).
    • The SIP credentials (User ID, Password, Auth ID) are correct.
    • The firewall is not blocking port 5060/UDP.
  • Call established but no sound: Check RTP ports (16384-16482) in the firewall. Check that the chosen codec is supported on both ends.
  • Echo or crackling: Reduce the microphone volume in the web interface ("Voice" > "Line 1" > "Audio Settings" > "Rx Gain" and "Tx Gain").
  • Fax not working: Switch to "Fax Passthru" mode with G.711u codec. Reduce fax speed to 9600 bps. Disable ECM (Error Correction Mode) on the fax if possible.
  • Cannot access web interface: Check that your PC is on the same network as the PAP2T. Use the voice menu to verify the IP. If the port was changed, try http://ip:8080.
  • DTMF dialing not recognized (voice server): Change "DTMF Tx Method" from "Auto" to "InBand" or "AVT" (RFC 2833) in the audio configuration.

Best Practices

  • Use a strong password for PAP2T web interface admin access.
  • Configure the PAP2T in HTTPS if possible to avoid interception.
  • Tag voice packets with a voice VLAN (802.1p = 5) for priority.
  • Use TFTP provisioning for batch deployments - avoids manual errors.
  • Maintain a centralized Excel file with the serial number (MAC), phone number, and location of each PAP2T.
  • Test each PAP2T before deploying it at the client site (in workshop).
  • Ensure the client's local network is properly dimensioned for VoIP (latency < 100 ms, loss < 1%, jitter < 30 ms).
  • Update the PAP2T firmware to the latest available version.
