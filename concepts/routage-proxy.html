Proxy Server (Squid)

← Back to Routing Guide

Definition

A proxy server is an intermediary between clients and remote servers. It intercepts client requests, forwards them to the destination server, then returns the response to the client. Squid is the most widely used open-source proxy software, known for its caching performance, filtering capabilities, and flexibility. There are two main types: forward proxy (outbound) and reverse proxy (inbound).

What is a proxy used for at Matrix Telecom?

Matrix Telecom uses a Squid proxy to offer its enterprise clients an Internet access filtering and bandwidth optimization solution:

  • Content filtering: Block access to websites by category (social networks, streaming, adult sites, etc.).
  • HTTP/HTTPS Cache: Cache frequently accessed content to reduce bandwidth usage.
  • Authentication: Control Internet access per user (via LDAP/AD).
  • Logging: Track employee Internet activity for compliance.
  • Bandwidth control: Limit bandwidth per user or per application.

How It Works

Forward Proxy (Outbound)

The forward proxy is placed between internal clients and the Internet. Clients configure their browser (or via a PAC file / Group Policy) to use the proxy. Squid receives the HTTP/HTTPS request, checks filtering rules, serves the page from cache if available, or downloads it from the remote server.

Reverse Proxy (Inbound)

The reverse proxy is placed in front of a web server (Apache, Nginx). It receives requests from external clients, forwards them to the internal server, and can provide caching (site acceleration), load balancing, and security (hiding the real server).

Key Features of Squid

  • Hierarchical cache: Squid can be configured as parent/child (cache peering) to optimize caching at the ISP level.
  • ACLs (Access Control Lists): Filtering by IP address, network, domain, URL regex, time, authenticated user.
  • ICAP (Internet Content Adaptation Protocol): Integration with antivirus (ClamAV) and content filters (SquidGuard, DansGuardian).
  • SSL Bumping: Interception and inspection of HTTPS traffic (decryption/re-encryption).
  • Authentication: Basic, NTLM, Kerberos, LDAP, RADIUS, Digest.
  • Logging: Detailed logs in native Squid format or Apache format (common/combined).
  • Bandwidth management: Bandwidth limitation per ACL using "delay pools".

Step-by-Step Configuration

Step 1: Installing Squid on Ubuntu/Debian

sudo apt update
sudo apt install squid apache2-utils -y
sudo systemctl enable squid
sudo systemctl start squid

Step 2: Basic Configuration (squid.conf)

# /etc/squid/squid.conf

# Listening port (default 3128)
http_port 3128

# Internal network ACLs
acl localnet src 192.168.0.0/16
acl localnet src 10.0.0.0/8
acl localnet src 172.16.0.0/12

# Allowed port ACLs
acl SSL_ports port 443
acl Safe_ports port 80          # http
acl Safe_ports port 21          # ftp
acl Safe_ports port 443         # https
acl Safe_ports port 70          # gopher
acl Safe_ports port 210         # wais
acl Safe_ports port 1025-65535  # unprivileged ports
acl Safe_ports port 280         # http-mgmt
acl Safe_ports port 488         # gss-http
acl Safe_ports port 591         # filemaker
acl Safe_ports port 777         # multiling http

# Do not allow CONNECT to non-SSL ports
acl CONNECT method CONNECT
http_access deny CONNECT !SSL_ports

# Rule: allow local network to access allowed ports
http_access allow localnet
http_access allow localhost

# Deny all other traffic
http_access deny all

Step 3: Cache Configuration

# Cache size and location
cache_dir ufs /var/spool/squid 10000 16 256
# 10GB cache, 16 first-level subdirectories, 256 second-level

cache_mem 256 MB    # Memory reserved for popular objects
maximum_object_size 50 MB
minimum_object_size 0 KB
maximum_object_size_in_memory 512 KB

# Refresh policy
refresh_pattern ^ftp:           1440    20%     10080
refresh_pattern ^gopher:        1440    0%      1440
refresh_pattern -i (/cgi-bin/|\?) 0     0%      0
refresh_pattern .               0       20%     4320

Step 4: Domain Filtering (block social networks)

# Create a blacklist file
sudo mkdir -p /etc/squid/blacklists
sudo nano /etc/squid/blacklists/social.txt

# Content:
# .facebook.com
# .twitter.com
# .instagram.com
# .tiktok.com

# In squid.conf, add:
acl social_networks dstdomain "/etc/squid/blacklists/social.txt"
http_access deny social_networks
http_access allow localnet
http_access deny all

# Reload Squid
sudo systemctl reload squid

Step 5: Authentication with Local Users

# Create a password file
sudo htpasswd -c /etc/squid/passwd user1
sudo htpasswd /etc/squid/passwd user2

# In squid.conf, add:
auth_param basic program /usr/lib/squid/basic_ncsa_auth /etc/squid/passwd
auth_param basic children 5
auth_param basic realm Matrix Proxy Authentication
auth_param basic credentialsttl 2 hours

acl authenticated proxy_auth REQUIRED
http_access allow authenticated
http_access deny all

# Note: place these rules AFTER the domain ACLs

Step 6: Delay Pools (bandwidth limitation)

# In squid.conf:
delay_pools 1
delay_class 1 2          # Class 2 = aggregate + per host
delay_parameters 1 5000000/50000000 1000000/5000000
# Aggregate limit: 50 Mbps max / 5 Mbps guaranteed
# Per host: 5 Mbps max / 1 Mbps guaranteed
delay_access 1 allow localnet
delay_access 1 deny all

Step 7: Reverse Proxy Configuration with Nginx

# /etc/nginx/sites-available/matrix-reverse-proxy
server {
    listen 80;
    server_name app.matrix.cm;

    location / {
        proxy_pass http://192.168.1.10:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_cache matrix_cache;
        proxy_cache_valid 200 1h;
    }
}

Practical Example at Matrix Telecom

Use Case: Squid proxy for Internet filtering of 150 employees of a client in Yaoundé.

Architecture:
  • An Ubuntu 22.04 server with Squid 5.x, installed in the Matrix datacenter.
  • Employees configured with transparent proxy (no browser configuration) via a NAT rule on the MikroTik router redirecting port 80 to Squid port 3128.
  • Authentication via Active Directory (NTLM) to track connections per employee.
  • Content filtering with SquidGuard: block social networks from 8am to 12pm.
  • Bandwidth limitation: 2 Mbps per user.
  • Logs centralized and analyzed with GoAccess for monthly reports.

NAT rule on MikroTik for transparent proxy: 
/ip firewall nat add chain=dstnat protocol=tcp dst-port=80 action=redirect to-ports=3128

Benefits:
  • Bandwidth savings (cache of frequent sites: 30% reduction).
  • Parental control and GDPR compliance (browsing logs retained 1 year).
  • Monthly reports provided to management.

Tools Used

Squid - Open-source proxy server software.
Installation: apt install squid
Main file: /etc/squid/squid.conf
Logs: /var/log/squid/access.log, /var/log/squid/cache.log

SquidGuard - Content filter integrated with Squid. Uses domain and URL blacklists.
Installation: apt install squidguard
Configuration: /etc/squidguard/squidguard.conf

GoAccess - Real-time web log analyzer. Compatible with Squid logs.
Usage: goaccess -f /var/log/squid/access.log -o report.html --log-format='%h %^[%d:%t %^] "%r" %s %b "%R" "%u"'

Apache mod_proxy - Proxy module for Apache HTTP Server. Allows configuring Apache as a reverse proxy.
Configuration: a2enmod proxy proxy_http proxy_balancer

Nginx - High-performance web server and reverse proxy. Used as a reverse proxy for applications hosted at Matrix.
Usage: Configuration via proxy_pass in location blocks.

Squid Analyse - Squid log analysis tool (generates graphs and reports).
Usage: apt install squidanalyse

PAC File (Proxy Auto-Config) - JavaScript file allowing browsers to automatically choose the proxy based on the requested URL.
Hosting: On an internal web server, for example http://proxy.matrix.cm/proxy.pac

Tip for the Intern

Good to know:
  • Master Squid ACLs: they are the core of filtering. Learn the acl name type value syntax.
  • For transparent proxy, clients have nothing to configure. It is ideal for businesses.
  • SSL Bumping is powerful but raises compliance issues (traffic decryption). Use it sparingly and inform users.
  • Squid logs are very verbose. Use analysis tools (GoAccess, SquidAnalyse) to exploit them.
  • Always test filtering rules on a test user before deploying globally.
  • Squid can be resource intensive (RAM for cache). Monitor performance.
  • Consider configuring a cache peer with another proxy (e.g., Matrix's) to optimize caching.

Exercise

Task 1: Install and Configure Squid as a Forward Proxy

Matrix Telecom uses Squid as a caching proxy for clients to reduce bandwidth usage and enforce web access policies. Installing Squid on an Ubuntu server, configuring basic ACLs, and testing the proxy is a practical skill for NOC interns supporting managed customer networks.

  1. SSH into a Linux server (or VM) and install Squid: sudo apt update && sudo apt install squid -y.
  2. Edit the configuration: sudo nano /etc/squid/squid.conf.
  3. Add an ACL for the internal network: acl internal_net src 192.168.1.0/24 and http_access allow internal_net.
  4. Ensure the default http_access deny all is the last line.
  5. Set the visible proxy name: visible_hostname Matrix-Proxy-Yaounde.
  6. Restart Squid: sudo systemctl restart squid and verify it's running: sudo systemctl status squid.
  7. On a client PC, set the proxy in browser to the server's IP on port 3128 and verify Internet access works.
  8. Check access logs: sudo tail -f /var/log/squid/access.log to see requests passing through.

Task 2: Configure a Transparent Proxy with iptables Redirect

At Matrix, transparent proxies are preferred for client networks because no per-device configuration is needed. In this task you will reconfigure Squid to act as a transparent proxy and redirect HTTP traffic at the router level.

  1. Edit /etc/squid/squid.conf and set: http_port 3128 intercept and http_access allow all (for the lab).
  2. Add an iptables rule to redirect HTTP traffic: sudo iptables -t nat -A PREROUTING -i eth0 -p tcp --dport 80 -j REDIRECT --to-port 3128.
  3. Restart Squid: sudo systemctl restart squid.
  4. On a client PC (no proxy configured in browser), visit an HTTP site — it should load without manual configuration.
  5. Verify the access log shows the client's real IP, not the proxy's IP.
  6. Test HTTPS sites — they should bypass the proxy (since Squid only intercepts port 80 by default).
  7. Add a second iptables rule to save the NAT configuration across reboots: sudo iptables-save | sudo tee /etc/iptables/rules.v4.

Troubleshooting

  • Proxy refuses connections: Check that Squid is running (systemctl status squid). Check rules in squid.conf.
  • Clients receive "Access Denied": Check ACLs and http_access rules. Check logs.
  • Cache not performing well: Check refresh_pattern. Increase cache size if needed (watch disk space).
  • Authentication not working: Check the auth helper configuration. Test with /usr/lib/squid/basic_ncsa_auth manually.
  • Squid does not start: Check configuration file with squid -k parse. Check /var/log/squid/cache.log.
  • Transparent proxy issue: Check the NAT rule on the router. Ensure Squid is listening on the redirected port.

Best Practices

  • Use whitelists for users who require specific access.
  • Generate monthly reports for managers.
  • Monitor logs to detect anomalies (attempts to access blocked sites, abnormal volumes).
  • Configure log rotation (logrotate) to avoid filling the disk.
  • Use HTTPS with PAC files to avoid man-in-the-middle attacks.
  • Document filtering exceptions (users, temporarily allowed sites).
