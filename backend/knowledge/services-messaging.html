Definition and Detailed Explanation

Email messaging is a fundamental service for any business. Matrix Telecom offers professional email hosting solutions for its clients, including dedicated or shared mail servers, domain management, anti-spam/antivirus security, and support for configuring email clients.

A complete email system consists of several components that interact to enable sending, receiving, and storing emails.

How It Works

Fundamental Protocols

SMTP (Simple Mail Transfer Protocol): Email sending protocol. It operates on port 25 (unencrypted), 587 (Submission with STARTTLS), or 465 (SMTPS with TLS). SMTP is a push protocol: it pushes the message to the destination server.

Email sending process:

  1. The email client (Outlook, Thunderbird) connects to the outgoing SMTP server (port 587) by authenticating.
  2. The sender's SMTP server (Matrix) queries the destination domain's DNS to find the MX (Mail Exchange) server.
  3. Matrix's SMTP server transmits the message to the recipient's SMTP server (port 25).
  4. The recipient's server delivers the message to the user's mailbox.

IMAP (Internet Message Access Protocol): Email receiving protocol. It keeps messages on the server and allows access from multiple synchronized devices. Port 143 (unencrypted) or 993 (IMAPS with TLS).

POP3 (Post Office Protocol version 3): Older receiving protocol that downloads messages to the client and deletes them from the server (by default). Port 110 (unencrypted) or 995 (POP3S with TLS). Not recommended for professional use as it does not sync between devices.

Email Security Protocols

SPF (Sender Policy Framework): DNS TXT record listing servers authorized to send emails for a domain. Example: v=spf1 mx ip4:192.168.1.0/24 ~all

DKIM (DomainKeys Identified Mail): Cryptographic email signing. The server signs each message with a private key, and the recipient server verifies the signature with a public key published in DNS.

DMARC (Domain-based Message Authentication, Reporting & Conformance): Policy telling the recipient server what to do if SPF and/or DKIM fail: none (nothing), quarantine (mark as spam), reject (reject).

Microsoft Exchange

Microsoft Exchange is the most widespread enterprise email solution. It offers:

  • Shared mailboxes, calendars, contacts, tasks
  • ActiveSync: mobile synchronization
  • OWA (Outlook Web Access): browser access
  • Archiving and retention
  • Server-side rules (Transport Rules)

Microsoft 365 (Exchange Online) is the cloud version. Some Matrix clients prefer on-premises Exchange for compliance or latency reasons.

Antispam

Anti-spam solutions protect mailboxes against unwanted emails, phishing, and malware:

  • DNSBL filtering (DNS-based Blackhole List): blacklists of servers known to send spam (Spamhaus, Barracuda).
  • Bayesian filtering: statistical analysis of email content.
  • Greylisting: the server temporarily refuses the first delivery from an unknown sender. Legitimate servers retry, spammers do not.
  • RBL (Real-time Blackhole Lists) and SURBL (Spam URI Realtime Blocklists).
  • Dedicated anti-spam gateway: physical or virtual appliance (e.g., Barracuda, SpamTitan, Proxmox Mail Gateway).

Postfix (SMTP server) — Open source SMTP server
The most widely used SMTP server on Linux. Handles email routing and delivery.
Usage:
# Installation
apt install postfix

# Main configuration (/etc/postfix/main.cf)
myhostname = mail.matrix.cm
mydomain = matrix.cm
myorigin = $mydomain
inet_interfaces = all
mydestination = $myhostname, localhost.$mydomain, $mydomain

# TLS security
smtpd_tls_cert_file = /etc/ssl/certs/matrix.cm.pem
smtpd_tls_key_file = /etc/ssl/private/matrix.cm.key
smtpd_tls_security_level = may
smtpd_sasl_auth_enable = yes

# Verification
postfix status
postfix reload
tail -f /var/log/mail.log

Rspamd / SpamAssassin — Anti-spam filter
Analyzes incoming emails and assigns them a spam score. If the score exceeds a threshold, the email is marked as spam or rejected.
Usage:
# Rspamd - web interface
https://mail.matrix.cm:11334
User: admin
Password: *******

# Default scores
- < 4: clean email
- 4 - 8: suspicious (marked as spam)
- > 8: rejected

# Useful commands
rspamadm stat                    # Statistics
rspamadm configwizard            # Configuration wizard
tail -f /var/log/rspamd/rspamd.log

# Test SPF/DKIM/DMARC rules
rspamadm dkim_keygen -d matrix.cm -s 2024
rspamadm sigtest -m message.eml

Tip for the Intern:
1. Email is a critical service. An email that does not go out or arrive can paralyze a business. Take the time to understand each step of the SMTP flow.
2. The most frequent errors at Matrix are DNS-related: incorrect MX record, missing SPF, unconfigured DKIM. Always check these three points.
3. Learn to read email headers. That is where the cause of delivery issues is found. In Outlook: File > Properties > Internet Headers.
4. Use online tools like MXToolbox to diagnose DNS/MX/SPF/DKIM configuration issues.
5. Never configure Outlook with POP3 for professional use. Insist on IMAP (but remember that some Cameroonian clients have unstable connections and prefer POP3).
6. At Matrix, ask which mail server is used, how mailbox backups are handled, and what the email retention policy is.
7. For quick troubleshooting: check if port 993 (IMAP SSL) and 587 (SMTP SSL) are accessible from the client's network. A simple Telnet or Test-NetConnection is sufficient.
