NanoStation M2 / M5 — Point-to-Point Links

← Back to Index

Definition

The NanoStation (M2 and M5 models) is a professional WiFi device from Ubiquiti Networks. It is designed to establish point-to-point (PtP) or point-to-multipoint (PtMP) links over distances of 1 to 15+ km. At Matrix Telecom, NanoStations are widely used to connect customers who cannot be served by fiber optic, using license-free frequencies (2.4 GHz for M2, 5 GHz for M5).

Operating Modes

1. Bridge Mode (Point-to-Point)

The most commonly used mode at Matrix. Two NanoStations are configured to create a transparent bridge between two Ethernet networks. One is in Station mode (AP-Client), the other in AP mode (Access Point). Clients connected on both sides are on the same subnet.

  • AP (Access Point): Matrix POP side. Emits the signal, connected to the distribution switch.
  • Station (Client): Customer side. Receives the signal, connected to the customer's router.

2. Station Mode (Client)

The NanoStation connects to an existing AP. Used to connect a single customer to a Matrix POP. The IP address is obtained via DHCP or configured statically.

3. Access Point Mode (WDS)

The NanoStation acts as a standard WiFi access point. Used to cover a limited area (a few hundred meters). Less common mode at Matrix, mostly used for temporary hotspots.

airOS Interface

All NanoStations use Ubiquiti's airOS firmware, accessible via a web browser at the device's IP address. The interface offers:

  • Main: Dashboard with signal indicators, speed, connections
  • Wireless: WiFi configuration (SSID, frequency, channel, power)
  • Network: Network configuration (IP, mask, gateway, DHCP)
  • Advanced: Advanced settings (distance, QoS, VLAN)
  • Services: Network services (SNMP, syslog, NTP)
  • System: Administration (password, backup, firmware, reboot)
  • Tools: Built-in tools (ping, traceroute, spectrum analyzer, antenna alignment)

Step-by-Step Configuration Guide

Step 1: Pre-Configuration at the Office

  1. Connect the NanoStation to a PoE adapter and to a PC via Ethernet
  2. Configure the PC's network interface to 192.168.1.0/24
  3. Open a browser and go to http://192.168.1.20
  4. Default credentials: admin / ubnt
  5. Change the password immediately (System > System Config)

Step 2: AP Side Configuration (POP)

  1. Network tab: Set static IP (e.g., 10.0.0.2/24)
  2. Wireless tab:
    • Mode: AP
    • SSID: Matrix-POP-Bastos-Link1
    • Frequency: 5 GHz (for M5)
    • Channel: 149 (DFS-free for urban areas)
    • Channel width: 40 MHz (20/40 MHz auto)
    • Power: 20 dBm (max regulatory)
    • Security: WPA2-AES (or WPA3 if supported)
  3. Advanced tab: Set the distance (e.g., 2000 meters)
  4. Apply changes (Apply + Reboot if necessary)

Step 3: Station Side Configuration (Client)

  1. Network tab: Set static IP (e.g., 10.0.0.3/24)
  2. Wireless tab:
    • Mode: Station
    • Select the SSID: Matrix-POP-Bastos-Link1
    • Enter the WPA2 key
    • Verify that the signal appears (RSSI)
  3. Apply changes
  4. Verify the connection: the AP should appear in the "Access Point" section

Step 4: Antenna Alignment

Alignment is the most critical step. A poorly aligned NanoStation can lose 10 to 20 dB of signal.

  1. Open airOS on the Station (client side)
  2. Go to Tools > Alignment Tool
  3. A real-time graph displays the signal strength (RSSI)
  4. One person adjusts the antenna (azimuth then elevation) while the other watches the signal
  5. Look for the maximum signal peak
  6. Final tightening of the mounting screws
  7. Target: RSSI > -65 dBm, SNR > 25 dB, CCQ > 90%

Step 5: Test and Validation

# Verify connectivity (from the NanoStation or a PC behind it)
ping 10.0.0.2 -n 20

# Measure throughput with iperf3 (server side on the AP)
iperf3 -s -p 5201

# Client side
iperf3 -c 10.0.0.2 -t 30 -p 5201

Radio Link Budget Calculation

The link budget allows predicting whether the link will be functional before even installing the equipment.

Formula: Received power = TX power + TX gain + RX gain - Cable losses - FSPL

FSPL (Free Space Path Loss) = 32.45 + 20 * log10(distance in km) + 20 * log10(frequency in MHz)

Example for a NanoStation M5 link at 3 km:
- TX power: 26 dBm
- AP gain: 16 dBi
- Station gain: 16 dBi
- Cable losses: 0.5 dB (very low because integrated PoE)
- FSPL = 32.45 + 20*log10(3) + 20*log10(5800)
       = 32.45 + 9.54 + 75.27 = 117.26 dB
- Received power = 26 + 16 + 16 - 0.5 - 117.26 = -59.76 dBm

Result: -59.76 dBm (excellent, > -65 dBm)
Fade margin: (-59.76) - (-75) = 15.24 dB (very good margin)

Tools Used

airOS Web Interface
Usage:
  • Browser access to the NanoStation's IP
  • Check Main tab: signal, speed, CCQ, connections
  • Use Alignment Tool for fine antenna tuning
  • Spectrum Analyzer to find a clean channel
  • System > Backup to save configuration
  • System > Firmware Update to update firmware
Built-in Alignment Tool
Usage:
  1. In airOS > Tools > Alignment Tool
  2. A timeline graph displays received power (RSSI)
  3. A real-time level bar shows instant RSSI
  4. Adjust azimuth (horizontal) in 1-2° increments
  5. Wait 2-3 seconds for the graph to stabilize
  6. Mark the best angle, then adjust elevation (vertical)
  7. Repeat until maximum RSSI is obtained
Spectrum Analyzer (airOS)
Usage:
  • Go to Tools > Spectrum Analyzer
  • Start a scan on the 5 GHz band (or 2.4 GHz for M2)
  • Analyze the graph: identify channels with the least interference
  • Choose a channel away from noise peaks
  • In dense urban areas, DFS channels (52-64, 100-140) are often cleaner
Ubiquiti Network Application (UNMS / UISP)
Usage:
  • Centralized management platform for all Ubiquiti devices
  • Automatic discovery of NanoStations on the network
  • Real-time monitoring: signal, speed, uptime
  • Remote firmware updates
  • Alerts for link loss or weak signal

Practical Case at Matrix Telecom Yaoundé

Link Between Two Buildings in Yaoundé

Matrix needs to connect a professional customer (law firm) located on the 8th floor of a building in Mfoundi, 2.3 km from the Matrix Bastos POP.

Situation:

  • Matrix Bastos POP: rooftop terrace, direct line of sight to Mfoundi
  • Mfoundi client: balcony facing Bastos, no obstacles between the two points
  • Distance: 2.3 km measured on Google Earth
  • Customer requirements: 100 Mb/s symmetric, SLA 99.9%

Deployed Solution:

  1. Equipment: 2x NanoStation M5 (one at POP, one at customer)
  2. POP side: AP mode, channel 120 (DFS), power 20 dBm, SSID "Matrix-BASTOS-MFO-01"
  3. Client side: Station mode, connect to SSID, static IP 10.10.5.2/24
  4. Alignment: Final RSSI of -58 dBm, SNR 32 dB, CCQ 97%
  5. Throughput: 135 Mb/s measured with iperf3 (sufficient for the promised 100 Mb/s)
  6. Security: WPA2-AES + MAC filtering + VLAN 100 isolated for the client
  7. Protection: Surge protector on the Ethernet cable between NanoStation and switch

Result: Stable link for 18 months, no major incidents. Maintenance: semi-annual check of screw tightness and connector cleanliness.

Tip for the Intern

Tip:
  • Always perform a Line of Sight (LoS) test before deploying a NanoStation. A single tree can cause 20 dB of signal loss.
  • Use the online tool link.ubnt.com to simulate the link before installation. Enter the GPS coordinates of both points.
  • Never exceed the regulatory power allowed by ART Cameroon (20 dBm EIRP in 5 GHz).
  • For long distances (> 5 km), configure the ACK distance in Advanced > ACK Timeout (value = distance in miles).
  • Protect outdoor Ethernet cables with conduit and waterproof enclosures (IP65 minimum).
  • Use Ethernet surge protectors between the NanoStation and the switch to prevent lightning damage.
  • Record configuration parameters (IP address, SSID, channel, frequency) in the customer folder.
  • Update NanoStation firmware regularly. Ubiquiti fixes security vulnerabilities.
  • During frequent thunderstorms, disconnect the NanoStation's Ethernet cables (surge protection).
  • Learn to read airOS logs (System > System Log) to identify disconnection causes.

Best Practices

  • Always verify frequency compatibility with local regulations.
  • Prefer DFS channels (52-64, 100-144) in urban areas to avoid WiFi interference.
  • Use VLAN tagging to isolate customer traffic from management traffic.
  • Set a strong password (12+ characters) on each NanoStation.
  • Disable unused ports and services (public SNMP, telnet, HTTP if HTTPS is available).
  • Perform an annual link check: tightness, alignment, performance.
