Definition and Detailed Explanation

A domain name is a human-readable address (e.g., matrix.cm) that corresponds to a numeric IP address. DNS (Domain Name System) is the phonebook of the Internet: it translates domain names into IP addresses that computers can understand.

Matrix Telecom offers domain name registration (registry) and DNS hosting (name servers) services for its professional customers. Matrix can be a domain reseller through AFNIC (.cm, .fr, etc.) or other registries.

A domain name consists of several parts:

  • TLD (Top-Level Domain): The rightmost part (.com, .org, .cm, .fr, .net)
  • Second-level domain: The main name (e.g., matrix in matrix.cm)
  • Subdomain: Optional prefix (e.g., mail.matrix.cm, www.matrix.cm)

How It Works

DNS Hierarchy

DNS operates in a hierarchical manner:

  • Root Servers: 13 clusters of servers (managed by ICANN, Verisign, etc.) that know the servers for each TLD. Expressed as a.root-servers.net through m.root-servers.net.
  • TLD Servers: Manage a specific TLD (.com is managed by Verisign, .cm by AFNIC). They know the name servers for each registered domain.
  • Authoritative Name Servers: Owned by the registrar or hosting provider. They contain the actual DNS records for a given domain (IP addresses, mail servers, etc.).

DNS Resolution Step by Step

When you type www.google.com in a browser:

  1. The browser first checks the local operating system cache.
  2. If not found, the query is sent to the configured recursive DNS resolver on the machine (usually the ISP's or Google's 8.8.8.8).
  3. The resolver queries the root server: "Where is .com?"
  4. The root server responds with the address of a .com TLD server.
  5. The resolver queries the .com TLD server: "Where is google.com?"
  6. The TLD server responds with the authoritative name servers for google.com (ns1.google.com, ns2.google.com).
  7. The resolver queries an authoritative name server: "What is the IP of www.google.com?"
  8. The name server responds with the A (IPv4) or AAAA (IPv6) record.
  9. The resolver returns the IP to the browser, which can now establish the connection.

DNS Record Types

  • A: Maps a domain name to an IPv4 address (e.g., 142.250.201.4)
  • AAAA: Maps a domain name to an IPv6 address (e.g., 2a00:1450:4007:80b::2004)
  • CNAME: Alias from one name to another (e.g., www.matrix.cm to matrix.cm)
  • MX: Specifies mail servers for a domain with priority (e.g., mail.matrix.cm priority 10)
  • NS: Defines the authoritative name servers for the domain
  • TXT: Arbitrary text data (used for SPF, DKIM, DMARC, ownership verification)
  • SRV: Location of specific services (SIP, LDAP, XMPP)
  • PTR: Maps an IP address to a domain name (reverse resolution)
  • SOA: Start of Authority - contains administrative information about the DNS zone

Domain Registration

Registration process via Matrix:

  1. Check domain name availability (via whois or registry API)
  2. Order through the registry (AFNIC for .cm, Verisign for .com, etc.)
  3. Define DNS servers (Matrix's or the client's)
  4. Configure DNS records on authoritative servers
  5. DNS propagation (can take from a few minutes to 48 hours)

DNS Hosting

Matrix can host DNS zones for its clients. Matrix's authoritative DNS servers respond to recursive queries from internet users. Matrix generally maintains 2 DNS servers for redundancy (ns1.matrix.cm, ns2.matrix.cm).

Practical Example at Matrix Telecom

Example: A customer company wants to create a website for their business "Solutions Cameroun". They order the domain solutions-cameroun.cm through Matrix and want their site to be accessible at www.solutions-cameroun.cm with emails at contact@solutions-cameroun.cm.

Steps:
1. Check availability:
   whois solutions-cameroun.cm
   # Result: "No entries found" - available

2. Registration with AFNIC (.cm)
   Form: customer information, admin, technical, billing contacts
   Payment: 25,000 FCFA / year (estimated price)

3. DNS configuration on Matrix's servers:
   Zone file: solutions-cameroun.cm

   $TTL 3600
   @   SOA ns1.matrix.cm. admin.matrix.cm. (
        2025070101  ; Serial (YYYYMMDDNN)
        3600        ; Refresh
        1800        ; Retry
        604800      ; Expire
        86400       ; Minimum TTL
   )
   @   NS  ns1.matrix.cm.
   @   NS  ns2.matrix.cm.
   @   A   192.168.1.100     ; Web server IPv4
   www A   192.168.1.100     ; www subdomain
   @   MX  10 mail.solutions-cameroun.cm.
   mail    A   192.168.1.101     ; Mail server
   @   TXT "v=spf1 mx a ~all"   ; SPF anti-spam

4. Verify deployment:
   nslookup www.solutions-cameroun.cm
   dig solutions-cameroun.cm MX

Tools Used

nslookup — DNS lookup (Windows/Linux)
Command-line tool for querying DNS servers and obtaining records.
Usage:
# Query A record
nslookup google.com
nslookup www.matrix.cm

# Query a specific type
nslookup -type=MX google.com
nslookup -type=NS google.com
nslookup -type=TXT google.com
nslookup -type=SOA google.com
nslookup -type=CNAME www.microsoft.com

# Query a specific DNS server
nslookup google.com 8.8.8.8

# Reverse lookup
nslookup 8.8.8.8
dig — Domain Information Groper (Linux/Mac)
More advanced tool than nslookup, widely used by network administrators for DNS troubleshooting.
Usage:
# Basic query
dig google.com
dig google.com ANY

# Specific record type
dig google.com MX
dig google.com NS
dig google.com TXT
dig google.com SOA

# Query a specific server
dig @8.8.8.8 google.com

# Reverse lookup
dig -x 8.8.8.8

# Follow the resolution path (trace)
dig +trace google.com

# Short format
dig google.com +short
whois — Domain information
Tool that queries the WHOIS database to obtain domain registration information: registrant, expiration date, contacts, DNS servers.
Usage:
# Basic information
whois google.com

# Cameroonian domain (.cm)
whois matrix.cm

# Check domain availability
whois domainepris.cm
# If "NOT FOUND": domain is available
# If "registrar": domain is already registered

# Additional details
whois -h whois.verisign-grs.com google.com

BIND (named) — Reference DNS server
If Matrix hosts its own DNS servers, BIND is the most widely used software.
Usage:
# Installation (Ubuntu/Debian)
apt install bind9

# Zone configuration (named.conf.local)
zone "solutions-cameroun.cm" {
    type master;
    file "/etc/bind/zones/solutions-cameroun.cm.db";
};

# Reload BIND
rndc reload
# or
systemctl reload bind9

# Check logs
tail -f /var/log/syslog | grep named

# Test the zone
named-checkzone solutions-cameroun.cm /etc/bind/zones/solutions-cameroun.cm.db

Tip for the Intern:
1. Master dig and nslookup. They are the most important tools for DNS troubleshooting at Matrix.
2. Understand DNS propagation: changes are not instantaneous. The TTL in the SOA record indicates cache duration.
3. To test a new site, use the hosts file before changing DNS: edit C:\Windows\System32\drivers\etc\hosts (Windows) or /etc/hosts (Linux).
4. Emails are particularly sensitive to DNS: MX, SPF, DKIM, DMARC must be correctly configured for deliverability.
5. Always check the serial in the SOA zone when modifying a zone. If the serial does not increase, slave servers will not propagate changes.
6. At Matrix, ask which registrar is used for .cm domains and how automatic renewal works.
