Definition

Servers are the core of Matrix Telecom's and its clients' IT infrastructure. They provide essential services such as authentication (Active Directory), name resolution (DNS), IP address assignment (DHCP), web hosting (Apache/Nginx) and virtualization (VMware, Hyper-V, Proxmox). Matrix uses two main families: Windows Server for enterprise environments and Linux (Ubuntu/Debian) for specific services and core infrastructure.

What are servers used for at Matrix Telecom?

  • Active Directory: Centralized management of users, computers, group policies (GPO) for enterprise clients.
  • DNS: Authoritative name servers for client domains (matrix.cm, etc.) and recursive resolution for the Internet.
  • DHCP: IP address assignment to Matrix network clients and enterprise clients.
  • Web Hosting: Apache/Nginx servers for client websites.
  • Virtualization: VMware vSphere / Hyper-V / Proxmox for shared hosting of clients in the Matrix datacenter.
  • Database: MySQL/MariaDB, PostgreSQL for client applications.
  • Email: Exchange Server (Windows) or Postfix/Dovecot (Linux) for professional emails.
  • Backup: Backup servers (Veeam, Bacula, rsync) for client data backup.

Windows Server

Active Directory & DNS

# Promote server to domain controller (PowerShell)
Install-WindowsFeature -Name AD-Domain-Services -IncludeManagementTools
Import-Module ADDSDeployment
Install-ADDSForest -DomainName "matrix.cm" -DomainMode WinThreshold -ForestMode WinThreshold

# Verify AD
Get-ADDomainController -Filter *
Get-ADUser -Filter * | Format-Table Name, Enabled

# DNS Configuration
Add-DnsServerPrimaryZone -Name "client1.cm" -ZoneFile "client1.cm.dns"
Add-DnsServerResourceRecordA -ZoneName "client1.cm" -Name "www" -IPv4Address "10.0.0.10"

DHCP Server

# Install DHCP role (PowerShell)
Install-WindowsFeature -Name DHCP -IncludeManagementTools
Add-DhcpServerv4Scope -Name "LAN Client" -StartRange 192.168.1.100 -EndRange 192.168.1.200 -SubnetMask 255.255.255.0
Set-DhcpServerv4OptionValue -ScopeId 192.168.1.0 -Router 192.168.1.1 -DnsServer 192.168.1.10,8.8.8.8

# Authorize DHCP server in AD
Add-DhcpServerInDC -DnsName "dhcp1.matrix.cm"

User Management (PowerShell)

# Create a new user
New-ADUser -Name "John Doe" -GivenName John -Surname Doe `
  -SamAccountName jdoe -UserPrincipalName jdoe@matrix.cm `
  -Path "OU=Employees,DC=matrix,DC=cm" -AccountPassword (ConvertTo-SecureString "P@ssw0rd!" -AsPlainText -Force) `
  -Enabled $true

# Add user to a group
Add-ADGroupMember -Identity "VPN_Access" -Members jdoe

GPO (Group Policy Object)

# These operations are normally done via the "Group Policy Management Console"
# PowerShell example: create a GPO and link to an OU
New-GPO -Name "ProxySettings" -Comment "Configure proxy for all users"
Set-GPRegistryValue -Name "ProxySettings" -Key "HKCU\Software\Microsoft\Windows\CurrentVersion\Internet Settings" `
  -ValueName ProxyEnable -Type DWord -Value 1
Set-GPRegistryValue -Name "ProxySettings" -Key "HKCU\Software\Microsoft\Windows\CurrentVersion\Internet Settings" `
  -ValueName ProxyServer -Type String -Value "192.168.1.50:3128"
New-GPLink -Name "ProxySettings" -Target "OU=Employees,DC=matrix,DC=cm"

Linux Server (Ubuntu/Debian)

Basic Configuration

# Update and install basic tools
sudo apt update && sudo apt upgrade -y
sudo apt install net-tools curl wget htop iotop ufw fail2ban -y

# Network configuration (netplan)
sudo nano /etc/netplan/01-netcfg.yaml
# /etc/netplan/01-netcfg.yaml
network:
  version: 2
  ethernets:
    eth0:
      addresses:
        - 10.0.0.10/24
      routes:
        - to: default
          via: 10.0.0.1
      nameservers:
        addresses: [8.8.8.8, 1.1.1.1]
sudo netplan apply

DNS Server (BIND9)

sudo apt install bind9 bind9utils -y

# /etc/bind/named.conf.local
zone "client1.cm" {
    type master;
    file "/etc/bind/db.client1.cm";
};

# /etc/bind/db.client1.cm
$TTL 86400
@       IN  SOA ns1.client1.cm. admin.client1.cm. (
            2026070101 ; Serial
            3600       ; Refresh
            1800       ; Retry
            604800     ; Expire
            86400 )    ; Negative TTL
;
@       IN  NS  ns1.client1.cm.
@       IN  A   10.0.0.10
www     IN  A   10.0.0.10
mail    IN  A   10.0.0.11

sudo systemctl restart bind9

DHCP Server (ISC DHCP)

sudo apt install isc-dhcp-server -y

# /etc/dhcp/dhcpd.conf
subnet 192.168.1.0 netmask 255.255.255.0 {
    range 192.168.1.100 192.168.1.200;
    option routers 192.168.1.1;
    option subnet-mask 255.255.255.0;
    option domain-name-servers 10.0.0.10, 8.8.8.8;
    option domain-name "client1.cm";
    default-lease-time 86400;
    max-lease-time 172800;
}

host client-printer {
    hardware ethernet AA:BB:CC:DD:EE:FF;
    fixed-address 192.168.1.50;
}

sudo systemctl restart isc-dhcp-server

Apache Web Server

sudo apt install apache2 -y

# Create a VirtualHost
sudo nano /etc/apache2/sites-available/matrix-client.conf

<VirtualHost *:80>
    ServerName www.client1.cm
    ServerAdmin admin@matrix.cm
    DocumentRoot /var/www/client1
    ErrorLog ${APACHE_LOG_DIR}/client1_error.log
    CustomLog ${APACHE_LOG_DIR}/client1_access.log combined
</VirtualHost>

sudo mkdir -p /var/www/client1
sudo chown -R www-data:www-data /var/www/client1
sudo a2ensite matrix-client.conf
sudo systemctl reload apache2

Nginx Web Server (reverse proxy + HTTPS)

sudo apt install nginx certbot python3-certbot-nginx -y

sudo nano /etc/nginx/sites-available/matrix-app

server {
    listen 443 ssl;
    server_name app.matrix.cm;

    ssl_certificate /etc/letsencrypt/live/app.matrix.cm/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/app.matrix.cm/privkey.pem;

    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    }
}

sudo ln -s /etc/nginx/sites-available/matrix-app /etc/nginx/sites-enabled/
sudo nginx -t && sudo systemctl reload nginx

Tools Used

Windows Server Tools:
- Hyper-V Manager: Management of virtual machines on Windows Server.
- Active Directory Users & Computers: Management of AD users and groups.
- Group Policy Management Console: Creation and management of GPOs.
- DNS Manager: DNS zone configuration.
- DHCP Manager: DHCP scope and lease management.
- PowerShell: Automation of all Windows Server tasks.
- Remote Desktop Services: Remote access to Windows servers.

Linux Server Tools:
- SSH: Remote access to Linux servers. ssh admin@10.0.0.10
- systemctl: systemd service management. systemctl status apache2
- journalctl: Log viewing. journalctl -u nginx -n 50 --no-pager
- htop/iotop: Real-time CPU/RAM and disk monitoring.
- ufw: Simple firewall. ufw allow 80/tcp
- fail2ban: Protection against SSH brute-force attacks.
- rsync: File synchronization and backups. rsync -avz /data/ backup@10.0.0.20:/backup/
- cron: Scheduling recurring tasks.
- Proxmox Web UI: Web interface for managing VMs and containers (port 8006).

Multi-platform:
- VMware vSphere: Management of ESXi hosts and VMs via vCenter.
- Veeam Backup & Replication: Backup of Windows and Linux VMs.
- Ansible: Server configuration automation.
- Docker / Docker Compose: Application containerization.
- PuTTY / Windows Terminal: SSH clients.

Practical Example at Matrix Telecom

Use Case: Shared server infrastructure in the Matrix datacenter in Yaoundé.

Architecture:
  • 3 Proxmox hosts in a cluster (HA) for virtualization.
  • 1 Windows Server 2022 as DC (AD, DNS, DHCP) for Matrix infrastructure.
  • 1 Windows Server 2022 dedicated to monitoring (Zabbix, PRTG).
  • 5 Linux VMs (Ubuntu 24.04) hosting client websites (Apache/Nginx).
  • 1 Veeam backup server (Windows) with 90-day retention.
  • 1 Zimbra mail server (Linux) for client emails.

New client (website) deployment procedure:
  1. Create a VM on Proxmox: 2 vCPU, 4 GB RAM, 50 GB disk.
  2. Install Ubuntu 24.04 LTS with network configuration (static IP from client pool).
  3. Install Apache, PHP, MySQL.
  4. Configure VirtualHosts for the client's domains.
  5. Configure DNS zones on the Windows DNS server (A, MX, CNAME records).
  6. Configure Nginx reverse proxy for SSL (Let's Encrypt).
  7. Add the VM to Zabbix monitoring.
  8. Configure Veeam backup (snapshot + daily backup).
  9. Provide the client with FTP/SFTP access and connection information.

Automated deployment script (Ansible): 
---
- name: Deploy client web server
  hosts: client_vm
  become: yes
  tasks:
    - name: Install Apache and PHP
      apt:
        name:
          - apache2
          - php
          - php-mysql
          - libapache2-mod-php
        state: present
        update_cache: yes
    - name: Enable Apache modules
      apache2_module:
        name: "{{ item }}"
        state: present
      loop:
        - rewrite
        - ssl
    - name: Create VirtualHost
      template:
        src: vhost.conf.j2
        dest: "/etc/apache2/sites-available/{{ domain }}.conf"
    - name: Enable site
      command: a2ensite {{ domain }}.conf
    - name: Restart Apache
      service:
        name: apache2
        state: restarted

Tip for the Intern

Good to know:
  • Windows Server and Linux are complementary. At Matrix, Windows is used for AD and client workstations, Linux for web services and virtualization.
  • Master the basics of PowerShell and Bash shell: these are the daily tools of a system administrator.
  • Virtualization is ubiquitous. Understand the concepts of VM, container (LXC/Docker), snapshot, HA, live migration.
  • Always use SSH with keys rather than passwords on Linux servers.
  • Document your infrastructure: IP addressing, passwords (via a manager), topology, software versions.
  • Automate everything that can be automated (Ansible, shell scripts, PowerShell). Save time and avoid errors.
  • Monitor your servers: Zabbix, Nagios, PRTG. Configure alerts for critical events.
  • Apply security updates regularly (apt update && apt upgrade, Windows Update).

Troubleshooting

  • Windows Server won't start: Use safe mode (F8 at startup). Use DSRM (Directory Services Repair Mode) for AD.
  • DNS not resolving: Check the service (systemctl status bind9), logs, zone permissions, firewall rules.
  • SSH connection refused: Check SSH config (/etc/ssh/sshd_config), authorized keys, firewall (ufw status).
  • Apache not serving pages: Check VirtualHosts (apache2ctl -S), /var/www permissions, error logs.
  • Proxmox VM won't start: Check resources (memory, disk), status via qm status <id> or pct status <id>.
  • Backup fails: Check disk space on target, network permissions, backup tool logs.
  • AD issue: Use dcdiag and repadmin /replsum to diagnose replication problems.

Best Practices

  • Follow the principle of least privilege for administrator accounts.
  • Use dedicated service accounts (no personal accounts for services).
  • Configure log rotation (logrotate on Linux, Event Log size on Windows).
  • Separate networks: management, production, backup, DMZ.
  • Use SSL certificates everywhere (Let's Encrypt for exposed services).
  • Perform regular backup restore tests.
  • Maintain an up-to-date inventory of all servers (IP, OS, services, versions).
