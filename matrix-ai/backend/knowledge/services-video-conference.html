Definition and Detailed Explanation

Video conferencing is a technology that enables real-time audiovisual communication between multiple participants located in geographically distant locations. Telework (remote work) heavily relies on these tools to maintain collaboration within teams.

At Matrix Telecom, video conferencing and telework are key services for Cameroonian businesses, especially since the rise of hybrid work. Matrix assists its clients in selecting, deploying, and optimizing solutions (Microsoft Teams, Zoom, Google Meet) on their network infrastructure.

The main market tools:

  • Microsoft Teams: Integrated with Microsoft 365, used by most enterprises. Offers chat, video, file sharing, Office integration.
  • Zoom: Leader in video conferencing, known for reliability and ease of use. Webinars and breakout rooms.
  • Google Meet: Integrated with Google Workspace. Simple, lightweight, no client installation required.
  • Cisco Webex: Enterprise solution with advanced security features.
  • Jitsi Meet: Open source, self-hosted. Interesting solution for Matrix customers who want data control.

How It Works

Video Conferencing Platform Infrastructure

Modern platforms use a client-server architecture with media servers (SFU - Selective Forwarding Unit) that receive video/audio streams from each participant and redistribute them to others. This approach saves upload bandwidth for participants.

  • SFU (Selective Forwarding Unit): The server receives N streams and sends each participant N-1 streams (except their own). This is the architecture of Zoom, Teams, Meet.
  • MCU (Multipoint Control Unit): The server mixes all streams into a single stream. To avoid: one slow participant degrades quality for everyone.
  • P2P (Peer-to-Peer): Direct communication between 2 participants without an intermediary server. For small meetings (2-4 people).

Codecs and Bandwidth

Modern codecs offer excellent quality at reasonable bitrates:

  • H.264: Widely supported standard. Good compression, acceptable quality.
  • H.265 (HEVC): Better compression than H.264 (30-50% bandwidth savings).
  • VP8/VP9: Google's free codecs, used by Chrome and Google Meet.
  • AV1: Latest codec, superior compression, requires recent hardware.

Quality of Service (QoS) for Video Conferencing

To ensure a smooth experience, the network must be optimized:

  • Latency: Below 150 ms (ideal < 50 ms). High latency delays the conversation.
  • Jitter: Below 30 ms. High jitter causes stuttering and freezing.
  • Packet loss: Below 0.5% for audio, below 1% for video.
  • Traffic prioritization: Mark RTP packets with DSCP EF (46) for voice and AF41 (34) for video.

Network Configuration for Video Conferencing

Platforms use specific port ranges that need to be opened on the firewall:

  • Microsoft Teams: UDP 3478-3481, TCP 443, TCP 5060 (SIP)
  • Zoom: UDP 8801-8810, TCP 443, TCP 444
  • Google Meet: UDP 19305-19309, TCP 443, TCP 5222, TCP 5228
  • Cisco Webex: TCP 443, TCP 8443, UDP 9000-9999

Practical Example at Matrix Telecom

Example 1: Matrix deploys Microsoft Teams with network optimization for a client SME with 30 employees who want to adopt telework 2 days a week.

QoS Configuration on the Client's MikroTik Router:
# Mark Teams traffic
/ip firewall mangle
# Detect Teams traffic by ports
add chain=prerouting protocol=udp dst-port=3478-3481
  action=mark-packet new-packet-mark=teams-media passthrough=no
add chain=prerouting protocol=tcp dst-port=443
  action=mark-packet new-packet-mark=teams-signal passthrough=no

# Mark SIP/RTP flows (for integrated VoIP telephony)
add chain=prerouting protocol=udp dst-port=5060
  action=mark-packet new-packet-mark=voip-signal passthrough=no
add chain=prerouting protocol=udp dst-port=10000-20000
  action=mark-packet new-packet-mark=voip-media passthrough=no

# Configure priority queues
/queue tree
add name=global max-limit=50M
add parent=global packet-mark=voip-media priority=1
add parent=global packet-mark=teams-media priority=2
add parent=global packet-mark=teams-signal priority=4
add parent=global packet-mark=no-mark priority=8

Tip for the Intern:
1. Video conferencing quality is directly linked to network quality. Before any important meeting, check latency, packet loss, and available bandwidth.
2. Download and use the official testing tools for each platform (Zoom Test, Teams Call Analytics).
3. QoS is your best friend: prioritize video conferencing traffic on client routers you configure at Matrix.
4. If a client complains about freezing: first check WiFi (signal, interference), then the Internet connection, then the PC itself (CPU, RAM).
5. Train clients on best practices: close unnecessary applications, use an Ethernet cable if possible, avoid sharing the connection with heavy downloads during meetings.
6. At Matrix, ask which video conferencing solutions are most requested by clients and how you can optimize them.
