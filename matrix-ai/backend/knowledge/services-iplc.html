IPLC — International Private Leased Circuit

← Back to Index

Definition and Detailed Explanation

An IPLC (International Private Leased Circuit) is a private, dedicated connection linking two distant sites located in different countries. Unlike standard Internet where traffic is shared with other users, an IPLC offers guaranteed, exclusive bandwidth for the customer, with strict Service Level Agreements (SLA).

IPLCs are historically based on SDH/SONET (fiber optic) technology, but modern versions often use MPLS or Ethernet over fiber (E-Line). The connection is point-to-point (Layer 2) and does not traverse the public Internet.

IPLC is used by organizations that need to transfer sensitive data between international sites with maximum reliability, security, and predictability:

  • Banks and financial institutions
  • Embassies and diplomatic organizations
  • Multinational companies
  • Telecommunications operators
  • Interconnected data centers

How It Works

Underlying Technology

IPLC leverages several transport technologies:

  • SDH/SONET: Synchronous Digital Hierarchy, a fiber optic transmission standard with speeds of 155 Mbps (STM-1), 622 Mbps (STM-4), 2.5 Gbps (STM-16), 10 Gbps (STM-64).
  • DWDM: Dense Wavelength Division Multiplexing allows transporting multiple signals on a single fiber using different wavelengths (light colors).
  • Ethernet over fiber: Modern variant using 1G/10G/100G Ethernet links with MPLS or VLAN encapsulation.

Relationship with MPLS

Traditional IPLC is a Layer 1 or Layer 2 point-to-point circuit. However, many operators now offer IPLS (IP Leased Line) or MPLS Layer 2 VPN services that emulate an IPLC over an MPLS network. The customer sees a point-to-point connection while in reality, their traffic is transported via MPLS labels across the operator's network.

The SLA (Service Level Agreement)

The IPLC contract defines key performance indicators (KPIs):

  • CIR (Committed Information Rate): Minimum guaranteed bandwidth.
  • EIR (Excess Information Rate): Additional possible bandwidth if the network allows.
  • Maximum latency: Transit time between both endpoints (e.g., 50 ms maximum between Yaoundé and Paris).
  • Uptime: Percentage of time the circuit is operational. 99.9% = ~8 hours downtime per year.
  • MTTR (Mean Time To Repair): Maximum repair time in case of failure (4h, 8h, 24h).

IPLC Deployment at Matrix

When a customer subscribes to an IPLC at Matrix:

  1. Matrix identifies point A (customer site in Yaoundé) and point B (remote site, e.g., London).
  2. Matrix has an existing international link (submarine fiber via WACS, SAT-3, or ACE).
  3. A logical circuit is configured on Matrix's edge routers using transport VLANs or MPLS L2VPN.
  4. A dedicated network interface is provisioned at the customer site with a CPE router configured in point-to-point mode.
  5. Tests are performed (ping, iperf) to verify throughput, latency, and packet loss.
  6. Continuous monitoring is set up (SNMP, Zabbix) to verify SLA compliance.

Practical Example at Matrix Telecom

Example: An international bank based in Yaoundé needs a private connection with its headquarters in Douala and an office in Paris. Matrix sets up a 10 Mbps IPLC between Yaoundé and Douala, and a 5 Mbps IPLC between Yaoundé and Paris.

Configuration at the customer site in Yaoundé:
# MikroTik configuration for IPLC
/interface vlan
add name=iplc-douala vlan-id=100 interface=sfp1
add name=iplc-paris vlan-id=200 interface=sfp1

/ip address
add address=10.99.1.1/30 interface=iplc-douala
add address=10.99.2.1/30 interface=iplc-paris

/ip route
add dst-address=10.0.0.0/8 gateway=10.99.1.2
add dst-address=172.16.0.0/12 gateway=10.99.2.2

# Bandwidth monitoring
/tool graphing interface add
The bank can now transfer sensitive data with guaranteed bandwidth and latency under 10 ms between Yaoundé and Douala.

Tools Used

Cisco CLI — Cisco router configuration

# SSH connection to the router
ssh admin@192.168.1.1

# View interfaces
show ip interface brief

# Configure a serial interface for IPLC
configure terminal
interface Serial0/0/0
 ip address 10.99.1.1 255.255.255.252
 encapsulation ppp
 bandwidth 10000
 no shutdown
 end

# Verify the circuit
show interfaces serial0/0/0
show ip route
ping 10.99.1.2

Iperf3 — Network performance testing
Standard tool for measuring effective throughput between two machines.
Usage:
# Server (site A)
iperf3 -s -p 5201

# Client (site B)
iperf3 -c 10.99.1.1 -p 5201 -t 30 -i 5
iperf3 -c 10.99.1.1 -p 5201 -u -b 100M -t 30  # UDP test

# Result: reports throughput, packet loss, and jitter

1. IPLC is Matrix's most critical product in terms of SLA. Understand the difference between CIR and EIR.
2. Learn to read an SLA contract and check if penalties are applicable.
3. Master network diagnostic commands (ping, traceroute, iperf) to validate a circuit.
