VPN & MPLS

← Back to Index

Definition and Detailed Explanation

VPN (Virtual Private Network) is a technology that creates an encrypted tunnel between two points over a public network (Internet) to guarantee data confidentiality and integrity. VPN allows remote sites or mobile employees to securely access the company network.

MPLS (Multiprotocol Label Switching) is a transport technique that directs packets using labels instead of IP addresses. Unlike regular Internet VPN, MPLS is a carrier service that operates within the operator's private network.

At Matrix Telecom, these two technologies are complementary: MPLS for the internal backbone interconnecting Matrix's sites (Yaoundé, Douala, Bafoussam, etc.), and VPN (IPSec/OpenVPN) for remote access by customers and employees.

How It Works

Site-to-Site VPN

Permanent connection between two remote sites using VPN routers at both ends. Each local network sees the other network as if it were directly connected. The most common protocols:

  • IPSec: The industry standard for site-to-site VPN. Uses AH (Authentication Header) and ESP (Encapsulating Security Payload) protocols. Works in Tunnel mode (entire IP packet is encrypted) or Transport mode (only payload is encrypted).
  • GRE (Generic Routing Encapsulation): Tunneling protocol that encapsulates packets of various protocols within IP. Often combined with IPSec for encryption (GRE over IPSec).
  • IPSec + IKEv2: More stable modern version, resistant to network changes (mobility).

Remote Access VPN

Temporary connection of individual users to the company network:

  • OpenVPN: Open source, based on SSL/TLS, runs on UDP/1194 or TCP/443. Very flexible and secure.
  • WireGuard: Modern, integrated into the Linux kernel since version 5.6, much faster than OpenVPN and IPSec.
  • L2TP/IPSec: Combination of Layer 2 Tunneling Protocol and IPSec for encryption. Native on most OS.
  • SSL VPN: Access via web browser (e.g., Fortinet SSL VPN, OpenVPN over TCP/443).

IPSec Protocol in Detail

IPSec works in two phases:

  1. Phase 1 (IKE SA): Establishment of a secure channel between the two peers. Peers authenticate each other (via pre-shared key or certificates) and negotiate security parameters (encryption algorithm, hash function, Diffie-Hellman group). Uses UDP port 500.
  2. Phase 2 (IPSec SA): Negotiation of parameters for the actual data traffic. Session keys are generated. Packets are encrypted with AES (256 bits) and authenticated with SHA-256.

MPLS in Detail

MPLS works by inserting a label (4 bytes) between the Layer 2 header (Ethernet) and the Layer 3 header (IP). This label contains:

  • 20 bits: Label value
  • 3 bits: Experimental (CoS - Class of Service)
  • 1 bit: Bottom of Stack (indicates if this is the last label)
  • 8 bits: TTL (Time To Live)

Key MPLS components:

  • LSR (Label Switch Router): MPLS router that reads/swaps/removes labels.
  • LER (Label Edge Router): Router at the edge of the MPLS network. It adds the label to incoming packets (push) and removes the label from outgoing packets (pop).
  • LSP (Label Switched Path): Path that packets take through the MPLS network.
  • VRF (Virtual Routing and Forwarding): Virtual routing instance within an MPLS router to isolate VPN customers from each other (MPLS L3VPN).

Practical Example at Matrix Telecom

Example 1 - Matrix MPLS Backbone: Matrix interconnects its three sites (Yaoundé headquarters, Douala agency, Bafoussam agency) via a private MPLS network. Each site has a MikroTik CCR (Cloud Core Router) configured for MPLS.

# MPLS configuration on MikroTik (Yaoundé)
# Enable MPLS on interfaces
/mpls interface
add interface=sfp1
add interface=sfp2

/interface bridge
add name=loopback

/ip address
add address=10.255.1.1/32 interface=loopback  # Router ID

/routing ospf instance
set 0 router-id=10.255.1.1

/routing ospf network
add network=10.255.0.0/16

/mpls ldp
set enabled=yes transport-address=10.255.1.1

/mpls ldp interface
add interface=sfp1
add interface=sfp2

# Verification
/mpls ldp neighbor print
/mpls forwarding-table print
Example 2 - IPSec VPN for a client: A banking client wants to connect its Douala branch to its headquarters in London via an IPSec tunnel over the Internet.

# MikroTik configuration - Client site in Douala
/ip ipsec proposal
set 0 enc-algorithms=aes-256-cbc auth-algorithms=sha256

/ip ipsec peer
add address=89.100.1.1/32 secret=MyPrivateKey123
add exchange-mode=ike2

/ip ipsec policy
add src-address=192.168.100.0/24 dst-address=10.0.0.0/8
  peer=89.100.1.1 tunnel=yes

/ip firewall nat
add chain=srcnat out-interface=ipsec-tunnel action=accept

# Verification
/ip ipsec active-peers print
/ip ipsec installed-sa print

Tip for the Intern:
1. Understand the difference between "full tunnel" VPN (all traffic goes through the VPN) and "split tunnel" (only traffic to the company network goes through the VPN).
2. In production, never expose OpenVPN on UDP port 1194 directly. Change the port or use an exotic port to avoid automatic scans.
3. MPLS is invisible to end users. If you are at Matrix, verify how the MPLS backbone interconnects sites: look at MPLS labels in a Wireshark capture.
4. At Matrix, client VPNs are often configured on MikroTik. Ask to see an example of IPSec configuration and an OpenVPN configuration.
5. IPSec debugging can be complex. Use /ip ipsec active-peers print (MikroTik) and show crypto isakmp sa (Cisco).
6. Remember: VPN = confidentiality + authentication; MPLS = performance + isolation.
